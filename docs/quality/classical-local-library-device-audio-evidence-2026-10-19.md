# Classical Local Library Native Audio Evidence

Date: 2026-10-19

## Scope

This evidence covers foreground local-file playback through the production
`JustAudioLocalPlaybackController` on an iOS Simulator and an Android
emulator. It does not claim human-audible output, real-device speaker behavior,
or musical-performance quality.

## Fixtures

`apps/classical_local_library/tool/generate_audio_fixtures.dart` creates two
deterministic test-only files:

- `assets/audio_test/movement_1.wav`
- `assets/audio_test/movement_2.wav`

Both are 2.4-second, 22,050 Hz, 16-bit mono PCM WAV files with synthetic
arpeggiated tones. Each has 100 ms start/middle/end marker tones and a known
100 ms silent window. They contain no third-party recording or human
performance. The generator is the source of truth; files are intentionally
small and reproducible.

SHA-256:

- `movement_1.wav`: `7a61385f3d45dae593a8af2315f6f43a4536526851686fd3e5edac80de8d2c8d`
- `movement_2.wav`: `f199b9d1513e7d08236ad4a3396d0b8716eb386c31b95fd862a5015046830b36`

`dart run tool/generate_audio_fixtures.dart --check` compares committed files
with deterministic generated bytes. The pure Dart validator also verifies
canonical RIFF/PCM metadata, duration, marker frequency estimates, and the
silent window before native playback begins.

## Native Run

Target: iPhone 17 Simulator, iOS 26.5

Command:

```sh
cd apps/classical_local_library
flutter test integration_test/audio_playback_integration_test.dart \
  -d 179447AC-F99C-4746-B9C1-CDA653EA9B2D
```

Result: passed.

The integration test copies both validated assets to the app temporary
directory, opens the production SQLite database, and uses the real `just_audio`
adapter. It verified queue loading, position advancement, pause/resume, seek
including the middle-marker time, explicit next, natural completion,
playback-history persistence, playback-position restore, recovery after
stop/new queue load, corrupt-WAV decoder failure recovery, replacing an active
queue without a stale native event restoring the old item, and disposal without
later playback-state events.

Android target: Pixel Tablet Emulator, Android 15 API 35 (`emulator-5554`)

The existing AVD was started without installing a new SDK or system image. Both
installed `adb` binaries saw the same device, then Flutter discovered it and
installed the test APK. The same native integration test completed with exit
code 0 on 2026-10-19.

The Android toolchain still reports duplicate `adb` binaries and unaccepted SDK
licenses. They did not prevent this run, but remain environment maintenance
risks rather than app-code defects.

AAC-in-M4A target: the repository-generated `movement_1_aac.m4a` was loaded,
timed, played, and stopped by the same production adapter on both emulators.
It is 22,050 Hz mono AAC generated from the synthetic PCM source with macOS
`afconvert`; no external recording was added.

ALAC-in-M4A target: on 2026-10-20, the repository-generated
`movement_1_alac.m4a` was loaded, timed, played, advanced beyond 300 ms, and
stopped by the production adapter on the iPhone 17 iOS 26.5 Simulator. It is
22,050 Hz mono ALAC generated from the same synthetic PCM source with macOS
`afconvert`. Android and physical-device behavior were not run or inferred.

On 2026-10-19, device discovery was repeated with `flutter devices`,
`adb devices -l`, and `xcrun simctl list devices`. No physical iOS or Android
device was connected. The iPhone 17 Simulator and Pixel Tablet emulator each
ran the same WAV/AAC-in-M4A integration test again. This is native
decoder/state-machine evidence only, not a speaker, route, or human-listening
result.

Pure-Dart state evidence is independent of these native runs. A small reference
model is compared with `FakeLocalPlayer` for three fixed seeds (`20261019`,
`20261020`, `20261021`), 16 scenarios per seed, and 24 generated commands per
scenario. Failure output includes the seed, scenario, command index, command
sequence, and a path-free `PlaybackStateTrace`.

The native test also has a 45-second test timeout and a bounded ten-iteration
soak loop. It alternates synthetic WAV and AAC-in-M4A, exercises concurrent seek
requests followed by pause/resume/stop, and records a path-free trace on timeout.
The bound prevents this evidence from becoming an indefinite endurance test.
The updated test passed on both the booted iPhone 17 Simulator and Pixel Tablet
Android 15 emulator on 2026-10-19; each in-test playback sequence completed in
about seven seconds, excluding build and installation time.

## Limits

- No person directly confirmed audible sound from either emulator.
- `재생 진단`의 청감 선택은 자동 청감 결과가 아니라 물리 기기 사용자가 직접 고르는 수동 feedback이다. 복사되는 JSON은 schema version, generic platform, synthetic fixture ID, container/codec, transport boolean, failure kind와 이 선택만 포함한다. 개인 파일, 감상 이력, 기기 식별자, native exception, 네트워크 전송을 사용하지 않는다.
- 사용자가 명시적으로 전달한 JSON은 `dart run tool/validate_playback_diagnostic_report.dart`의 표준 입력으로만 검토할 수 있다. 도구는 네트워크나 자동 저장을 사용하지 않고 fixture 회귀 가능성만 요약한다.
- Fixture byte integrity and native decoder/state transitions are automated;
  physical acoustic output and listening quality are not.
- AAC/ALAC other than the synthetic M4A fixtures, FLAC, MP3, OGG, and OPUS
  still need per-device compatibility and listening-quality
  verification.
- Background playback, lock-screen controls, audio focus refinement, headphone
  button behavior, gapless playback, and crossfade are not in scope.
