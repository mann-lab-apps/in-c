# 실음 보기의 첫 검증 범위

2026-11-23 승인 범위는 모든 마디와 보표의 이조가 일정한 단일 파트의 읽기 전용 보기다. **보기 → 실음 보기**로 화면을 전환하고 기보음으로 돌아가 편집한다. 선택과 재생에는 원본 ID를 사용한다. 프로젝트 본문과 PDF·MusicXML 사본은 기보음으로 저장하며, 실음 상태는 세션 안에서만 유지한다. 코드 심벌의 표준 표기와 명시된 이조 간격을 적용하고 정확히 표시할 수 없는 경우 이유를 안내한다. 실음 입력·PDF, 다중 파트와 가변 이조의 전환은 후속 범위다. [제품 검증](handoff.md#고정-이조-단일-파트의-실음-보기)

## 두 파일의 실제 비교

같은 B♭ 클라리넷 한 파트의 기보 C장조와 실음 B♭장조 대조군을 만들었다. MuseScore 4.7.5의 정상 종료 출력과 Studio의 네 Electron 경로에서 출력한 MIDI가 같은 음높이 58·64·68·69를 사용했다. 외부 PDF와 Studio 화면에서 F♯와 B♮이 있는 기보 및 E♮과 A♮이 있는 실음 표기를 확인했다. 이 비교는 두 파일의 조판과 재생을 검증했다. MuseScore는 상태줄에서 같은 악보의 실음 표시를 전환하며, 이번 검증은 별도 입력을 사용했다. [MuseScore 이조와 실음](https://handbook.musescore.org/notation/pitch/transposition.md#transposed-and-concert-pitch)

실음 MusicXML의 `for-part`는 별도의 이조 파트보를 만들 때 사용하는 값이다. Studio는 해당 파트 설정 손실을 가져오기에서 안내하고 현재 악보의 음높이를 보존한다. 이 경고를 보기 기능의 지원으로 집계하지 않는다. [MusicXML concert-score](https://www.w3.org/2021/06/musicxml40/musicxml-reference/elements/concert-score/) · [MusicXML for-part](https://www.w3.org/2021/06/musicxml40/musicxml-reference/elements/for-part/)

## 후속 설계

- 첫 구현 후보는 기존 기보 데이터에서 계산하는 실음 보기다. 현재 이조 설정 명령은 문서의 재생 이조를 변경하므로 보기 전환에 사용하기에는 맞지 않는다. 같은 음표 ID, 선택, 커서, Native 문서 내용과 기존 MIDI를 유지하는 조건을 확인한다.
- 기보음에 쓰던 임시표를 문자 그대로 옮기면 E♮이 E♭으로 바뀌는 경우가 있다. 보기에서는 이조된 조표와 직전 같은 음이 만든 상태를 기준으로 임시표를 다시 판단한다. 입력을 지원할 경우 음표 입력·음높이 변경의 역변환과 이명동음 정책을 정한다. 코드 심벌과 보표별·마디 중간의 이조는 범위를 결정한다.
- 첫 단계에서 편집은 기보 보기에서 진행하고, PDF를 실음으로 변환하는 출력은 별도 설정으로 결정하는 안을 검토한다. 저장과 기본 MusicXML의 기보 및 이조 표현을 유지한다. 실음 MusicXML 사본은 `concert-score`·`for-part`를 보존할 범위부터 정한다.
- 가져오기에서는 명시적 제자리표와 `<alter>`가 생략된 경우의 음높이 보존을 검증했다. 기존 직접 입력의 임시표 상속은 보기·입력 계약의 별도 기준이다.

## 클라리넷 한 파트의 수용 대조군

C장조 기보음 C4·F♯4·B♭4·B♮4를 B♭장조의 B♭3·E♮4·A♭4·A♮4로 투영했다. B♭3은 조표로 표시하고 나머지 세 음에는 임시표를 그린다. 기존 임시표 판단 함수로 얻은 결과가 실음 파일과 동일했다. 두 번째 음의 원본 ID로 선택 주소를 찾았고 원본 모델, Native의 악보 본문, 기본 XML과 MIDI 및 내부 타임라인이 일치했다. 시험 자료는 `out/parity-qa/check-pitch-view-contract.ts`와 `concert-display-contract.json`에 있다.

첫 후보는 한 파트에서 지원하는 고정 이조의 읽기 전용 보기다. 재생·탐색은 원본 ID와 커서 위치를 유지한다. 보기 전환 UI에서 선택·caret·스크롤 복귀와 명령의 활성화를 960/1400px에서 실제 검사한다. 실음 보기에서 편집을 지원한다면 E♮4 입력을 F♯4의 같은 재생 음높이로 역변환하고, 조표와 이전 임시표의 영향을 회귀로 대조한다. 코드 심벌과 구간·보표별 이조도 적용 범위를 결정한다.

첫 후보의 PDF는 기존 기보 값을 기본으로 사용하며 실음으로 출력하는 경로는 명시적 설정으로 검토한다. 전환은 저장된 악보나 기본 구조 유지 MusicXML의 이조를 변경하지 않는다. 보기의 적용 범위, 편집 허용과 PDF 옵션은 결정 대기다. 실제 전환 UI와 PDF 전환은 아직 구현하지 않았다.

현재 App은 화면의 `displayScore`와 출력용 `printScore`를 따로 만든다. 첫 후보는 화면 경로에서만 투영한다. 전환 전후에 같은 선택/커서 ID를 찾아 복귀하고, 전환 전에 시작한 포인터 제스처를 다른 표시 모드에 적용하지 않는 조건을 수용 검사에 포함한다.

## 서로 다른 이조 악기가 함께 있는 실음 대조

B♭ 클라리넷, E♭ 알토 색소폰, 플루트가 각각 기보 C4·F♯4·B♭4·B♮4를 연주하는 MusicXML은 고정 XSD를 통과했다. 같은 입력에서 Studio와 MuseScore 4.7.5 MIDI의 파트별 음높이와 0·1·2·3 시작 박이 일치했다. Studio의 네 음은 각각 1박, MuseScore의 클라리넷과 색소폰은 각각 479/480박, 플루트는 각각 91/96박이었다.

같은 음표와 이조를 가진 두 MuseScore Native 시료의 스타일 `concertPitch`만 0과 1로 바꿨다. 정상 종료한 두 A4 PDF에서 클라리넷과 색소폰의 음표 위치가 바뀌고 플루트의 음높이·임시표가 유지되는 것을 확인했다. 이 Native 시료에는 실음 조표 변화가 나타나지 않았다. 조표를 명시한 후속 대조의 실음 PDF와 Native에서 직접 만든 두 MIDI는 SIGABRT였으므로 결과 비교에서 제외했다. 실음 모드의 정상 MusicXML은 `concert-score`와 두 이조 파트의 `for-part`를 포함했고 고정 XSD를 통과했다. [MuseScore 보기 전환](https://handbook.musescore.org/notation/pitch/transposition#transposed-and-concert-pitch) · [MuseScore 4.7.5 스타일 정의](https://github.com/musescore/MuseScore/blob/v4.7.5/src/engraving/style/styledef.cpp)

Studio 시험용 변환은 같은 입력에서 조표를 기보 0·0·0에서 실음 −2·−3·0으로 지정했다. 12개 원본 음표 ID로 선택을 찾을 수 있었고 음높이 및 임시표를 확인했다. 클라리넷과 색소폰에서 첫 음은 지정한 조표가 처리하며, 뒤의 음들은 각 보표에 필요한 기호를 붙인다. 원본 모델, Native 악보 본문, 기본 XML·MIDI와 내부 타임라인은 동일했다. 일반 조표 이조, 실제 전환 UI, 입력 역변환, Studio PDF 적용 범위는 검증 대기다. 산출물의 해시와 성공·실패 기록은 `out/parity-qa/mixed-pitch-view-comparison.json`에 있다.

## 옥타브 이조와 마디 경계 해제

B♭ 베이스 클라리넷에 `diatonic=-1`, `chromatic=-2`, `octave-change=-1`을 지정했다. 두 번째 마디는 이조를 상속하면서 기보 조표를 C장조에서 G장조로 바꿨고, 세 번째 마디는 세 값을 0으로 적어 이조를 해제했다. 이 시료의 표기 투영에서 온음계 이동에는 옥타브당 7계단, 실음에는 12반음을 더했다. 조표에는 단순 음정만 적용해 실음 B♭장조·F장조·G장조를 얻었다. 기존 임시표 판단 함수, 원본 음표 ID 12개, 각 기보음으로의 역변환을 확인했다. 원본과 Native 악보 본문, 기본 XML·MIDI 및 내부 타임라인은 동일했다. [MusicXML transpose](https://www.w3.org/2021/06/musicxml40/musicxml-reference/elements/transpose/)

960×750·1400×750 실제 앱의 기보 파일과 별도 실음 대조군에서 동일한 MIDI 음높이·시작 박을 확인했다. 두 Studio PDF는 조표와 음 위치가 달랐다. 덧줄이 많은 실음 대조군의 셋째 마디는 다음 악보단으로 넘어갔다. 향후 보기 전환 검증은 화면 좌표와 별도로 선택 ID를 보존하고, 다시 조판한 위치로 커서가 이동하는지 확인해야 한다.

MuseScore 4.7.5의 정상 기보 MIDI는 첫 8음 `46,52,56,57` 두 묶음과 시작 박이 일치했다. 세 번째 마디에서 Studio는 `60,66,70,71`, MuseScore는 계속 `46,52,56,57`을 냈다. 파트의 악기 지정 없이 음높이를 직접 적은 실음 대조 MIDI는 정상 종료했고 12음과 시작 박이 Studio와 일치했다. 같은 대조의 MuseScore PDF 변환은 SIGABRT였다. Studio의 네 실제 출력 XML은 고정 XSD를 통과했다. 비교 자료는 `out/parity-qa/octave-pitch-view-reset-comparison.json`과 `bass-clarinet-pitch-view-reset-contract.json`에 있다. 이조 해제의 교환 차이를 기록했으며 Studio 전환 UI·편집·실음 PDF 정책은 결정 대기다.


## 온음계 이동을 생략한 XML과 실음 조표 범위

B♭ 클라리넷과 E♭ 알토 색소폰에서 `diatonic`만 제거하고 플루트를 대조로 유지했다. 고정 XSD가 입력과 Studio 출력을 확인했다. Studio는 생략을 Native 데이터와 재출력에서 보존했고 명시값 대조와 같은 MIDI 바이트를 만들었다. 두 앱의 정상 MIDI에서 파트별 12음의 음높이와 0·1·2·3박 시작이 일치했다. Studio의 각 음은 1박, MuseScore의 두 이조 파트는 479/480박, 플루트는 91/96박이다. MuseScore XML 재출력은 SIGABRT로 끝나 음이름 비교에서 제외했다. [MusicXML 이조 명세](https://www.w3.org/2021/06/musicxml40/musicxml-reference/elements/transpose/) · [MuseScore 4.7.5 이조 가져오기](https://github.com/musescore/MuseScore/blob/v4.7.5/src/importexport/musicxml/internal/import/importmusicxmlpass1.cpp#L2918-L2939)

화면의 조표 시험에서는 이조 간격 여섯 가지와 기존 조표 −7~+7의 90조합·음계 630음을 검증했다. 원래 이조 간격의 반음 변화가 유지됐다. 그대로 표현할 수 없는 조표 10건은 이명동음의 대체 조표가 있었다. 예를 들어 알토 색소폰의 기보 −7에서 계산한 실음 −10은 실음 +2로 바꾸고 음이름 이동도 함께 바꿀 수 있다. 반음만 +6인 경우 −6·+6 두 조표가 가능하므로 생략된 음이름 이동은 연주 음높이로 확정할 수 없다. 전체 3,150개 음과 임시표 조합 중 226건의 시험 투영에는 현재 이중 임시표 범위를 넘는 기호가 필요했다. 이명동음 선택과 표시 불가 안내는 제품 결정이 필요하다.

`concert-chromatic-only-comparison.json`에 외부 종료 코드와 양쪽 음높이·시작·지속, 파일 해시를 기록했다. `concert-key-range-probe.json`은 계산 대조다.

실음 보기에서 입력과 PDF에 적용할 범위는 기존 결정 대기 상태다. 이 계산은 원본에 손대지 않고 음이름을 시험했으며 제품 보기 전환은 아직 추가하지 않았다.


## 실음 보기의 코드 근음과 베이스음

기보 `Cmaj7/E`·`Dm7/A`를 0·2박에 넣은 세 파트와 실음을 직접 적은 대조를 만들었다. 시험용 표시 변환은 B♭ 클라리넷에서 `Bbmaj7/D`·`Cm7/G`, E♭ 알토 색소폰에서 `Ebmaj7/G`·`Fm7/C`를 얻었다. 플루트는 그대로다. 코드 종류·ID·박과 원본 Native·구조 XML·MIDI가 유지됐다. 정상 종료한 MuseScore 4.7.5 MusicXML 재출력은 두 별도 입력의 구조화된 근음·베이스·종류·박을 보존했다. 이 대조는 실제 Studio 전환 UI를 사용하지 않았다. [MuseScore 코드 심벌 이조](https://handbook.musescore.org/text/chord-symbols#transposing-instruments)

화면 투영의 수용 기준에 코드 이름과 참조 ID의 동시 보존을 추가한다. 텍스트 폭과 선택 영역에는 화면의 코드 이름을 사용한다. 구조화된 근음·베이스를 모두 확인할 수 있는 코드와 사용자 지정 텍스트를 구분한다. 사용자 지정 텍스트, 실제 공개 전환, 편집과 실음 PDF는 제품 범위를 정할 때 확인한다. `out/parity-qa/concert-harmony-projection.json`에 시험 좌표와 결과를 기록했다.


## 실음 보기에서의 옥타브선

옥타브선 경계의 회귀 악보에 B♭ 악기의 고정 이조를 넣어 시험했다. 기보음에서 악기 이조만 반영해 B♭장조에 놓고 원래 8va와 선택 ID를 유지한 투영은 원본과 같은 MIDI 59·77·71·76·64를 냈다. 화음과 앞꾸밈음의 기보음도 함께 옮겼고, 꾸밈음의 제자리표 값은 B♮3이다. 원본 Native 악보와 MIDI가 유지됐다. 먼저 8va를 실제 음높이에 합친 뒤 선도 남긴 대조는 구간의 음 세 개를 12반음 더 높였다. 8va를 화면에 유지하는 첫 보기 후보에서는 악기 이조를 원래 기보음에 적용하고 선을 별도로 그리는 조건을 확인한다.

이 결과는 화면 투영 데이터의 시험이며 실제 Studio 전환·편집·PDF 정책은 결정 대기다. `out/parity-qa/probe-concert-octave-contract.cjs`와 `concert-view-octave-contract/results.json`에 입력과 음높이 대조가 있다.


후속 공개 보기 검증에서 960/1400px의 8va·8vb, 화음과 앞꾸밈음 실제 잉크, 원본 선택 ID와 Native·MIDI·PDF를 확인했다. 이조한 기보음과 옥타브선은 별도로 표시된다. 실제 사본의 외부 재생 차이와 XML 경계 수정은 [인계](handoff.md#musicxml-옥타브선의-실제-경계)에 기록했다.


## 실음 보기에서 선택과 재생 위치를 유지하는 검증

이전 베이스 클라리넷 원본 하나를 960×750 dark와 1400×750 light의 같은 앱 창에서 열었다. 실제 App과 NotationPreview를 사용한 별도 검증 빌드에만 기보·실음 투영을 넣었다. 실제 앱의 공개 보기 전환, 실음 입력 역변환, PDF 옵션은 아직 설계 범위다.

두 폭의 실제 포인터로 기보 F♯4를 선택한 뒤 실음 E♮3로 그렸다. 같은 음표 ID와 파트·보표·마디·성부·틱, 선택과 키보드 초점을 보존했다. 실음 화면의 조표와 제자리표, 보표 아래 덧줄을 직접 확인했다. 입력 커서를 켠 대조에서는 투영을 바꿔도 주소와 틱이 같고 x 좌표는 새 조판을 따랐다. 검증 중 음표 입력은 수행하지 않았다.

같은 보기 안에서 첫째에서 셋째 음으로 드래그하면 세 음이 선택됐다. 투영만 바꾸고 기존 작업 상태를 공유하면 이전 드래그가 새 조판까지 이어졌다. 전환 때 NotationPreview의 기존 interactionOwner에 보기 모드를 반영하자 이전 드래그가 끊겼다. 이 경우 처음 음 선택을 보존했다. 제품 전환에서도 보기 모드를 작업 상태 구분에 포함하고 화면의 새 좌표만 사용하는 조건을 추가한다.

악보에 초점을 두고 Space로 음소거 재생을 시작했다. 실음에서 기보로 다시 그린 프레임에서도 재생 선은 같은 음표 ID와 주소를 가리켰고 선의 x 좌표는 새 음표에 맞았다. 두 폭의 첫 음표에서 재생 선 x는 약 146.72→109.64 SVG 단위, 음머리 y는 202→162였다. 이 검증은 화면의 재생 위치와 상태를 확인했다.

PDF는 시험 빌드에서 기보 데이터를 사용하는 기존 경로로 출력했다. 기보와 시험 실음 화면에서 내보낸 네 PDF는 각각 한 쪽이며 래스터가 일치했다. 두 화면 폭과 두 모드의 구조 XML·MIDI 바이트가 같고 Native 저장 악보 본문도 동일했다. MIDI 열두 음은 46·52·56·57·46·52·56·57·60·66·70·71을 0–11박에 각각 1박 연주했다. 이번 검증에서 MuseScore를 다시 실행하지 않았으며, 기존 실제 MuseScore 대조의 이조 해제 차이는 유지한다.

캡처, 실행 로그와 파일 해시는 out/parity-qa/concert-runtime-playing-reveal/에 있다. 초기 실행은 컴팩트 화면의 내보내기 설정과 상태줄이 클릭 위치를 가려 멈췄다. 파일 출력은 포인터 검증 뒤로 옮기고 실제 히트 검사와 Space 경로를 사용했다. 선택 중인 음표는 선택 색을 우선하므로 재생 선의 좌표를 실제 음표 위치와 대조했다. 제품 소스는 건드리지 않았고 공개 컨트롤·실음 편집·실음 PDF·청음은 미검증이다.
