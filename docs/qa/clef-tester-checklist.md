# Clef & Staff 외부 테스터 체크리스트

작성일: 2026-08-26

## 시작 전

- v1 RC 전체 실행 순서와 기록 양식은 `docs/qa/clef-v1-rc-qa-plan.md`를 먼저 확인한다.
- 실기기/외부장비 당일 실행표는 `docs/qa/clef-v1-device-qa-runbook.md`를 사용한다.
- 설치 후 런처/앱 이름이 `Clef & Staff`로 보이는지 확인한다.
- 앱 첫 화면 오른쪽 위 `테스트 정보`에서 앱 이름, 버전/build를 확인한다.
- 현재 소스 RC 후보는 `1.0.0+20`이다. 내부테스트 설치본은 Play Console 업로드 시점의 buildCode를
  함께 기록한다.
- TestFlight 또는 APK 설치 방식과 기기명/OS 버전을 기록한다.
- 가능하면 평소 쓰는 텍스트 PDF 악보 1개, 스캔/이미지 악보 1개, 큰 PDF 1개를 준비한다.
- iPad/TestFlight와 Android 태블릿/APK를 모두 테스트할 수 있으면 화면 크기별 표시 차이를 함께 기록한다.

## 필수 테스트

15분 안에 아래 흐름만 먼저 확인한다.

1. 빈 라이브러리에서 `악보 추가`로 PDF를 가져온다.
2. 가져온 직후 `정보 편집` 안내가 보이면 제목, 작곡가, 태그, 컬렉션, 그룹, 별점을 입력한다.
   사용자 필드의 `조성`/`장르`/`난이도`/`편성` 추천 칩으로 자주 쓰는 정보를 바로 추가하고,
   홈의 빠른 필터에서 같은 값으로 다시 찾을 수 있는지도 확인한다.
3. 정보를 아직 입력하지 않은 악보가 홈 `정리 필요` rail에 보이고 `정보 편집`으로 바로 열리는지
   확인한다.
4. 라이브러리 검색/정렬/필터로 방금 입력한 악보를 다시 찾는다. 작곡가/컬렉션/그룹/사용자 필드
   facet으로도 좁힐 수 있는지 확인한다. 검색어와 필터를 함께 적용했을 때
   홈 상단 `현재 조건` 칩으로 활성 조건이 보이고, 개별 삭제 또는 `전체 초기화`로 풀리는지 확인한다.
   컬렉션/그룹/사용자 필드 값이 많을 때는 `더 보기`에서 검색으로 좁혀 숨겨진 값도 선택할 수 있는지 확인한다.
5. 같은 PDF를 다시 가져왔을 때 새 카드가 조용히 중복 생성되지 않고 기존 악보를 연다는 안내가 보이는지
   확인한다.
6. PDF를 열고 이전/다음 페이지, 세로 스크롤, 1페이지 보기 중 하나를 확인한다. 세로모드에서는
   상단 toolbar를 좌우로 밀어 `필기 모드`, `페이지 정리`, `공연 설정`, `공연 모드`에 접근한다.
   viewer의 `악보 정보 편집`에서 제목/작곡가/태그/컬렉션/그룹/별점/추천 사용자 필드를 바로 수정할 수 있는지도
   확인한다.
7. 펜/형광펜/크레셴도/디미누엔도/오선/격자와 `Fine`, `D.C.`, `D.S.`, `Coda`, `rit.`, `accel.`
   같은 스탬프 중 몇 가지를 짧게 필기하고 앱을 다시 열어 복원되는지 확인한다.
8. 텍스트 주석을 하나 추가하고 다시 탭해 수정 또는 삭제한다.
9. 북마크를 추가하고 북마크 목록에서 해당 페이지로 이동한다. 긴 PDF/songbook은 가능하면
   `CSV 북마크 가져오기`로 `page,label` 또는 `label,page` CSV가 잘 병합되는지도 확인한다.
10. 튜너를 열었을 때 시작 버튼 없이 확대된 pitch history chart 안에 현재 음/cents/frequency/signal이 먼저 보이고, 기타 줄 맞춤이나 악기별
   preset 선택 없이 가장 가까운 음을 바로 표시하는지 확인한다.
11. 조용한 상태, 440/441/442Hz A4 quick action, 440Hz reference tone, 실제 악기 입력에서 sharp/flat
   표기, pitch history의 최신 값 왼쪽 고정/오래된 값 오른쪽 흐름/낮음·높음 방향, note 변경 시 선 끊김, `소리가 작거나 주변 소음이 큽니다`,
   `음을 잡는 중`, `조금 낮아요`, `조금 높아요`, `맞았습니다` 상태를 확인한다.
12. `세부 설정` 아래에서 sharp/flat 표기, 감지 엔진, A4 slider/history, 기준음/드론이 접근 가능한지
   확인한다. 기타 줄 맞춤, 악기별 preset, custom target/preset, target lock은 v1 UI에 보이지 않아야 한다.
13. 가능하면 Piascore 또는 무료 상용 튜너앱과 A4/E2/A2/C4/G4/C6 cents 값을 비교해 차이를 기록한다.
14. 메트로놈을 열어 BPM/박자, 8분/3연/16분 나눔, 0/1/2마디 카운트인, 박별 강세 패턴,
    Tap tempo, start/stop을 확인한다. 값을 바꾼 뒤 같은 악보를 다시 열었을 때 메트로놈 설정이
    유지되는지 확인한다. 같은 악보를 세트리스트 안에서 열었다면 세트리스트별 값으로 따로 저장되는지
    확인한다.
    기본값은 `소리 켬`이어야 하며, `tick 소리`를 끄면 화면 박자 표시만 사용하는 `시각만` 상태로
    이해되는지 확인한다.
    저장 중 페이지/필기가 바뀌어도 이전 상태로 돌아가지 않아야 한다. 제거된 세트리스트/곡의
    설정을 다시 만들거나 악보 자체 설정으로 바꾸지 않는지는 지연 저장 단위 테스트로 확인한다.
    BPM을 연속 변경하고 다시 열었을 때 마지막 값이 유지되는지 확인한다. 저장 순서/실패 후
    재시도는 로컬 테스트 범위이며 실제 박자 반응과 소리는 실기기에서 별도로 확인한다.
    설정 저장이 늦어도 BPM/박자 변경이 즉시 화면 박자에 반영되고, 정지/창 닫기 후 다시
    실행되지 않아야 한다. 저장 실패 안내와 재변경 경로는 지연 콜백 widget 테스트로 확인한다.
    카운트인 1/2마디의 마지막 박이 짧아지거나 다음 첫 박 강세가 일찍 나오지 않는지
    전체 창/미니 패널에서 비교한다. 나눔 없음/8분/3연/16분의 콜백 간격은 로컬 회귀 범위이며,
    빠른 BPM의 실제 청취 품질은 새 빌드에서 재확인한다.
15. 메트로놈/튜너 sheet의 작은 창 버튼으로 악보 위 mini panel을 띄우고 닫을 수 있는지 확인한다.
    메트로놈 mini panel은 시작/정지 버튼과 시각 박자 표시가 바로 보여야 하며, 소리가 작거나
    들리지 않는 환경에서도 현재 박을 눈으로 따라갈 수 있어야 한다.
16. viewer 첫 진입에서 왼쪽 `이전`, 가운데 `메뉴`, 오른쪽 `다음` tap zone 안내가 보이는지 확인한다.
    안내가 사라진 뒤 `터치 영역 다시 보기`를 눌러 같은 안내를 다시 볼 수 있는지도 확인한다.
17. 자동 스크롤을 시작한 뒤 수동 페이지 이동 시 정지되는지 확인한다.
    필기/정보 수정 직후 페이지를 넘겨도 내용이 되돌아가지 않아야 하며, 이전 페이지로 돌아온 뒤
    다시 열면 돌아온 위치가 복원돼야 한다. 오래된 페이지 콜백 경로는 controller 테스트로 확인한다.
    악보 정보 편집의 저장/취소 시 오류가 없어야 하며, 편집 중 변경된 페이지/즐겨찾기도 보존돼야 한다.
    대상 삭제 후 저장은 실패 이유를 안내해야 한다. 이 경로는 widget/controller 테스트로 검증한다.
    북마크 목록에서 이름 변경/삭제 후 다른 북마크와 최신 악보 정보가 유지되는지 확인한다.
    사라진 북마크 안내는 viewer 실사용 QA, 현재 목록 반영/저장 보존은 controller 테스트 범위다.
    즐겨찾기/고정을 빠르게 두 번 누르면 해제 상태로 돌아가며 페이지/정보는 유지돼야 한다.
    카드 재표시 전 연속 탭과 재로드는 widget/controller 테스트로 확인한다.
18. `테스트 정보`에서 `피드백 템플릿 복사`를 눌러 양식이 복사되는지 확인한다.
19. 새 라이브러리를 만들 때 기존 이름을 다시 입력하면 중복 안내가 뜨고 `열기` action으로 기존
    라이브러리에 진입하는지 확인한다.

## 선택 테스트

시간이 있으면 아래 항목을 추가로 확인한다.

1. JPG/PNG 이미지를 PDF 악보로 묶어 등록한다.
2. `악보 추가`에서 단일 PDF, 여러 PDF, 이미지 PDF를 가져오며 세트리스트에 추가하는 action이 보이는지 확인한다.
3. 악보 카드를 길게 눌러 일괄 선택 모드로 들어가고, 선택 상태가 체크/색상/선택 수로 분명한지
   확인한다. `현재 목록 전체 선택`과 `현재 목록 선택 해제`가 기대대로 동작하는지도 확인한다.
4. 여러 악보를 일괄 선택해 기존 또는 새 세트리스트에 한 번에 추가한다. 이미 들어간 악보가 있으면
   중복 skip 안내가 이해되는지 확인하고, 완료 안내의 `열기`로 세트리스트 상세를 바로 확인한다.
5. 같은 이름의 세트리스트를 만들거나 이름 변경하려 할 때 새 항목이 조용히 생기지 않고 중복 안내가
   보이는지 확인한다.
6. 빈 세트리스트 상세 화면에서 `악보 추가`가 바로 보이는지 확인한다. 세트리스트 상세의 `악보 추가`에서
   여러 악보를 검색/체크하거나 `현재 검색 결과 전체 선택`으로 한 번에 추가하고, 추가된 악보가
   세트리스트 끝에 순서대로 붙는지 확인한다.
7. 여러 악보를 일괄 선택해 기존 또는 새 컬렉션으로 묶고, 완료 안내의 `보기`로 컬렉션 필터를
   바로 열 수 있는지 확인한다.
8. 여러 악보를 일괄 선택해 `정보 편집`에서 태그/컬렉션/그룹/별점과 `조성` 같은 사용자 필드를
   한 번에 지정하고, 홈 빠른 필터로 다시 찾을 수 있는지 확인한다.
9. 여러 악보를 일괄 선택해 라이브러리에서 제거할 때 확인 dialog가 뜨고, PDF 원본 파일은 삭제하지
   않는다는 안내가 이해되는지 확인한다.
   좁은 화면에서도 선택 개수가 잘리지 않아야 한다. `선택 작업 더 보기`에서 컬렉션 지정,
   정보 일괄 편집, 라이브러리에서 제거에 접근하고, 선택이 없을 때는 비활성화되는지 확인한다.
   태블릿 가로 화면에서는 기존 선택 작업 바로가기 버튼을 유지한다.
   일괄 정보 편집의 `작곡가 변경`에 값을 넣어 선택 악보만 바뀌고 검색/작곡가 필터에서도
   찾을 수 있는지 확인한다. 입력을 비운 채 태그만 바꿀 때 기존 작곡가는 유지되어야 한다.
   제목이 비어 있는 악보도 파일명으로 구분되고, 제목을 바꾼 뒤에도 원본 파일명으로 검색되는지
   확인한다. 제목순 정렬, 세트리스트 이어보기/목록 복사에서도 같은 표시명을 써야 한다.
10. 세트리스트 상세에서 metadata가 비어 있는 악보도 파일명/작곡가 subtitle로 구분되는지 확인하고,
   drag handle로 순서를 바꾼다. 위/아래 버튼과 번호 배지 직접 순서 입력도 보조로 동작하는지
   확인한다. `목록 복사`가 순서/시작 쪽/시간/메모를 담는지 확인하고, 항목을 제거한 뒤
   `되돌리기`로 원래 위치에 복구되는지도 확인한다.
   정리 저장 실패를 주입한 로컬 테스트에서는 정상 악보와 정리된 목록이 유지되고,
   읽기 실패와 다른 안내가 나와야 한다. 저장 복구 후 다시 로드하면 정리 결과가 저장된다.
   지연 저장 성공 후 라이브러리를 다시 열어 필기/세트리스트 이름/참조 정리는 원래
   라이브러리에 저장되고 다른 라이브러리 목록과 자동 백업은 유지되는지 로컬 테스트한다.
   예전 백업에 빠진 곡의 예상 시간/메트로놈 설정이 남아 있어도 재시작 시 정리되고,
   남아 있는 곡의 설정과 이어보기 위치는 유지되어야 한다. 로컬 fixture로 별도 검증한다.
   추가 선택창을 열어 둔 동안 목록이 바뀌어도 기존 곡 순서가 유지되고 실제 추가/중복 수가
   안내되어야 한다. 빠른 연속 제거가 이전에 제거한 곡을 되살리지 않는지도 확인한다.
   대상 세트리스트가 사라졌다면 오류 화면 대신 `세트리스트를 찾을 수 없습니다.`가 표시되고,
   추가 작업은 성공/중복으로 안내하지 않아야 한다. 대기 중 리허설 설정도 저장하지 않는다.
   순번 입력창을 연 사이 목록이 바뀌면 `목록이 바뀌었습니다. 순서를 다시 선택해주세요.`로
   안내하고, 다시 연 입력창에서는 현재 목록 기준으로 이동되어야 한다.
   좁은 화면에서는 상세 제목이 읽히고 `세트리스트 작업 더 보기`로 목록 복사/복제/이름 변경/
   삭제가 가능해야 한다. 넓은 화면에서는 기존 작업 아이콘으로 바로 접근한다.
   리허설 또는 보기 프리셋을 적용해도 최신 곡 목록/이름과 변경하지 않은 메트로놈/이어보기
   정보가 유지되어야 한다. 빠진 곡의 설정은 다시 추가하지 않는다.
   같은 세트리스트를 여러 번 복제하면 `copy`, `copy (2)`처럼 서로 구분되는 이름이 생기고,
   원래 세트리스트의 이름과 내용은 바뀌지 않아야 한다.
   제거 `되돌리기`를 누르기 전에 악보나 세트리스트가 사라졌다면 복원 불가 안내가 나오고,
   없는 악보를 곡 수에 다시 포함하지 않아야 한다.
   일괄 추가를 선택하는 동안 악보가 라이브러리에서 제거되면 남아 있는 악보만 추가하고,
   빠진 악보 수를 중복과 구분해 안내해야 한다. 모두 빠졌다면 성공으로 안내하지 않는다.
11. 긴 PDF에 PDF 목차나 CSV 북마크를 넣은 뒤 viewer의 `북마크를 곡으로 나누기`를 실행한다.
   PDF/일괄 PDF/이미지/공유 가져오기 지연 중 라이브러리 전환의 로컬 회귀에서는 새 목록에
   이전 결과가 생기거나 뷰어/세트리스트 선택창이 열리지 않아야 한다. 파일 처리 단계와 이미
   시작된 저장 단계를 구분하며, 후자는 원래 라이브러리에만 저장된다. 실패 안내도 섞이지 않아야 한다.
   CSV 파일 읽기/형식 오류와 북마크 저장 실패 안내가 구분되는지 확인한다. 로컬 실패 주입에서
   저장 실패 후 재시도, 선택 중 악보 편집/제거/라이브러리 전환을 확인하며 다른 라이브러리에
   이전 CSV 결과가 들어가지 않아야 한다. 실제 파일 선택기 동작은 기기에서 별도 확인한다.
   원본 PDF는 그대로 두고, 북마크 구간별 새 악보 항목이 만들어지며 같은 작업을 다시 실행해도
   중복 항목이 생기지 않는지 확인한다. 완료 안내의 `세트리스트 만들기`를 눌러 북마크 순서대로
   곡 모음 세트리스트가 만들어지고, `열기`로 바로 상세 화면에 들어가는지도 확인한다.
   곡 모음 생성/추가 저장 실패 주입 시 곡 항목은 유지되고 `다시 시도`로 같은 목록에 담을 수
   있어야 한다. 생성/추가 각 단계의 지연 중 화면 종료/전환 후 불필요한 안내나 후속 저장이
   없는 것은 action widget 테스트로 확인한다. 실제 PDF 분할 메뉴 연결은 기기 QA로 남긴다.
   곡 분할 저장 자체의 실패도 임시 곡 항목을 성공으로 안내하지 않고 재시도할 수 있어야 한다.
   로컬 회귀에서는 원본 악보 메타데이터/PDF 참조 유지, 지연 성공의 라이브러리 격리,
   없는 대상/빈 북마크/이미 나눈 곡의 무변경 안내를 확인한다.
   각 곡이 자기 구간의 첫 표시 페이지에서 열리고, 다른 곡으로 향하던 점프/리허설 마크와 자동
   스크롤 범위가 따라오지 않는지 확인한다. 원본에서 구간 전체를 숨겼다면 새 곡에는 첫 페이지
   한 장이 표시되어야 하며, 원본의 숨김 설정은 유지되어야 한다.
   원본 책의 해당 구간에 적은 필기/텍스트가 분리 곡에도 있는지 확인한다. 분리 곡의 텍스트를
   수정/삭제해도 원본 책과 다른 분리 곡의 필기는 유지되어야 한다.
12. 세트리스트 중간 곡을 열었다가 홈으로 돌아와 `최근 세트리스트` rail에 `진행 n/m` pill,

    유지되는지 확인한다. 공유 PDF는 한 번만 백업/복원되며, 이름만 같은 다른 PDF는 합쳐지지 않는다.
    필요한 파일이 빠진 ZIP은 복원 오류 안내가 나오고 현재 라이브러리가 유지되어야 한다.
    같은 백업을 다른 라이브러리에서 다시 복원해도 기존 라이브러리가 사용하는 PDF/필기 파일은
    덮어쓰지 않아야 한다. 새 복원 항목은 독립 경로를 쓰며 같은 백업 안의 공유 PDF는 유지한다.
    저장 실패는 성공으로 표시하면 안 된다. 로컬 실패 주입 테스트에서는 JSON/ZIP 복원 중
    악보/설정/자동 백업 쓰기와 설정 삭제 실패 시 복원 직전 값을 되돌리고 재시도할 수 있는지 검증한다.

    이전 저장값 복구 및 다음 저장 재시도를 store 테스트로 검증한다. 화면 메모리 복구와
    실제 저장 공간 부족/강제 종료는 이 테스트의 통과 범위와 구분한다.
    개별 악보 편집 실패는 controller 테스트에서 저장된 상태로 복구하고, 지연 실패가
    최신 편집/삭제/라이브러리 전환을 취소하지 않는지 확인한다. 저장소를 다시 읽지 못하는
    경우와 일괄 편집/가져오기/세트리스트 메모리 복구는 별도 확인 범위다.
    필기 저장 오류가 난 경우 안내가 사라진 뒤 `취소할 필기가 없습니다` 같은 잘못된 후속
    안내가 나타나지 않아야 한다. PDF가 준비되기 전 취소/다시 적용도 crash 없이 동작해야 한다.

    S41: 필기 표시/숨김과 PDF 공유 포함/제외 저장 실패는 기존 저장값으로 복구하고
    오류 안내 후 재시도할 수 있어야 한다. 저장 중 연속 토글, 창 종료, 다른 화면 또는
    라이브러리로 이동하면 이전 작업의 완료/오류 안내를 표시하지 않는다. 실제 preferences

    성공/취소/오류 뒤에는 조작이 풀리고, 복원 중 공유된 PDF는 종료 뒤 처리되어야 한다.

- 라이브러리 비우기 실패 시 완료 안내 대신 재시도 안내가 표시되고 악보/세트리스트/보기 설정/
  즐겨찾기 필기 설정/자동 백업을 함께 복구하는지 확인한다. 원본 파일과 다른 라이브러리는
  제거하지 않는다. 창 종료/다른 화면 진입/라이브러리 전환 뒤 늦은 성공·실패 안내는 표시하지
  않는다. 비우기가 저장 큐에 들어간 뒤 악보/세트리스트/보기 설정/필기 프리셋을 편집하면
  늦은 비우기 완료가 새 화면 상태를 지우지 않아야 한다. 후속 악보/세트리스트 저장 실패와
  재시도도 로컬 검증했다. 겹치는 로드/큐 진입 전 경합/프로세스 강제 종료/롤백 자체 실패까지
  복구를 보장하지 않는다. 실제 저장소 지연과 장시간 사용은 실기기 QA다.

- 프로필/악보 조회만으로 프로필 목록을 다시 저장하지 않는다. 누락/잘못된 JSON의 기본값
  보정은 메모리에서만 하며, 조회 시 미지 필드를 포함한 저장 원문을 유지한다. 프로필 목록
  쓰기 실패가 악보 읽기를 막지 않는지 로컬 실패 주입 테스트로 확인했다. 명시적인 생성/
  이름 변경/삭제까지 미지 필드 보존을 보장하는 것은 아니며 기기 저장소 QA는 별도다.

- 일괄 악보 제거 시 악보 목록/세트리스트/자동 백업 중 저장 실패가 발생하면 성공 안내 없이
  복구를 시도하고 선택을 유지해야 한다. 저장 대기 중 라이브러리를 전환해도 새 라이브러리에
  제거 결과를 기록하지 않는다. 재시도 후 세트리스트의 곡별 메모/시작 페이지도
  정리되는지 확인한다. 원본 PDF는 삭제하지 않는다. 강제 종료나 롤백 자체 실패의 복구는 보장하지 않는다.

- 홈 다중 선택에서 기존/새 세트리스트 추가가 저장에 실패하면 선택 상태를 유지하고 오류를 안내한다.
  재시도 후 실제 저장 목록과 화면 구성이 일치해야 한다. 상세 화면의 이름/복제/삭제/악보 추가/
  리허설 설정/순서/제거/되돌리기도 실패 시 성공 안내를 표시하지 않아야 한다. 실패한 삭제는
  상세 화면을 닫지 않으며, 저장 대기 중 뒤로 간 화면에 늦은 오류를 표시하지 않는다.
  목록 생성 실패는 새 상세 화면으로 이동하지 않아야 한다. PDF/여러 PDF/이미지 가져오기는
  성공했지만 세트리스트 추가만 실패하면 악보가 라이브러리에 남았다는 안내를 확인한다.
  대상 선택 취소/추가 실패 뒤 뷰어가 자동으로 열리지 않아야 한다.
  이미 가져온 PDF에서도 취소/실패 시 기존 악보를 연다는 안내가 남지 않고, 성공 시 기존 항목을
  재사용하는지 확인한다. 일반 PDF 가져오기의 중복 안내와 실제 열기 동작도 확인한다.
- 최근 위치 저장에 실패해도 홈/세트리스트/다음 곡에서 유효한 악보는 계속 열고 저장 실패를
  안내해야 한다. 저장 대기 중 뒤로 가기/다른 화면/라이브러리 전환/곡 제거 뒤 늦은 완료는
  뷰어를 열지 않아야 한다. 로컬 지연/실패 주입 검증이며 실기기 저장소/실제 PDF 렌더링은 별도다.

- PDF/이미지/공유 가져오기 후 목록 저장 실패 시 성공 카드나 완료 안내가 남지 않는지 확인한다.
  복구를 위한 읽기도 실패하면 목록 복원을 보장하지 않는다. 이후 재시도 시 실패한 카드 때문에
  중복으로 잘못 판단하지 않아야 한다. native picker/cloud 입력과 기기 저장소 실패는 별도 QA다.

- 일괄 정보 편집/컬렉션 지정의 저장 실패는 성공 안내 대신 오류를 표시하고 선택을 유지해야 한다.
  저장된 목록으로 복구를 시도하되, 읽기도 실패하면 데이터 보존을 보장하지 않는다.
  지연 실패 뒤 재시도, 창 종료, 새 편집/라이브러리 전환은 로컬 회귀 범위이며 기기 저장소 QA는 별도다.

- 튜너의 synthetic sine/noise/time-series/pitch history 테스트는 통과했다. v1 UI는 Chromatic-only 첫 화면,
  세부 설정 접힘, 확대된 pitch history chart, sharp/flat 표기, A4 440/441/442 quick action/history, A4 보정 제안, adaptive noise
  floor 1차, weak signal normalization, clipping penalty, 저음 3배음 guard, `자동`/`기존`/`정밀 후보`
  감지 엔진, plucked string 회귀는 자동 테스트로 확인했다.
  Pitch history chart는 저장/백업 대상이 아닌 화면 내 임시 상태이며, 최신 sample을 왼쪽에 고정하고
  오래된 sample을 오른쪽으로 흘려 보여준다. 중앙선 label은 `0` 대신 현재 가장 가까운 음으로 표시하고,
  별도 meter/LED/input bar는 제거했다.
  기타 줄 맞춤, 악기별 preset, custom target/preset, target lock은 선택지 과다로 v1 UI에서 제외했다.
  실제 악기 기준 정확도, latency, 외부 마이크 안정성은 Android/iOS 실기기 검증 중이다.
- 2026-09-07 기준 현재 소스 RC 후보는 `1.0.0+20`이다. 실제 마이크 정확도/latency QA는 아직
  기록되지 않았다.
- iOS Simulator는 튜너 정확도 판단 대상이 아니다.
- 한글/비ASCII 텍스트 주석은 PDF export에서 제한될 수 있고, 이 경우 원본 PDF 공유로 fallback한다.
- 카메라로 종이 악보를 직접 촬영해 PDF로 만드는 내장 스캐너는 v1 범위가 아니다. v1에서는 이미
  만들어진 PDF/JPG/PNG를 가져오고, JPG/PNG 여러 장을 PDF 악보로 묶는 흐름을 확인한다.
- 필기 포함 PDF 공유는 편집 가능한 PDF annotation embed가 아니라 새 PDF 사본에 stamp하는 방식이다.
- crop/rotation/page hide는 원본 PDF를 바꾸지 않는 앱 metadata/display 중심 기능이다.
- URL link 제거는 synthetic link PDF fixture 기준으로 검증되어 있다. 실제 CamScanner/object stream
  PDF는 샘플 확보 후 별도 QA가 필요하다.
- S Pen pressure metadata/render/export와 stylus 직후 touch rejection window는 1차 구현되어 있다.
  Galaxy Tab S Pen/palm QA tuning은 남아 있다.
- Bluetooth 페달은 predefined/custom key dropdown과 진단 로그 기반 unknown key 설정을 지원한다.
  실제 key capture wizard는 후속 범위다.
- 방향키 방식 페달은 위/왼쪽이 이전 page, 아래/오른쪽이 다음 page로 동작해야 한다.
- 첫 page에서 이전, 마지막 page에서 다음을 누르면 버튼이 죽은 것처럼 보이지 않고 `곡 처음` 또는
  `곡 끝` 안내가 짧게 표시되어야 한다.
- 2026-09-07 연주자 피드백으로 다중 선택 강조, bulk setlist 추가, setlist drag reorder,
  최근 세트리스트 rail, page tap zone hint, paper/white viewer background, 메트로놈 subdivision/박별 강세 패턴/Tap tempo,
  세트리스트별 metronome override,
  고정형 mini tuner/metronome panel을 v1 hotfix에 반영했다. 실제 장비/연주 환경에서는 discoverability와
  장시간 사용성을 다시 확인한다.
- MobileSheets 비교와 연주자 피드백에 따라 새 metronome settings의 기본값은 `소리 켬`으로 둔다.
  명시적으로 `tick 소리`를 끈 기존/저장 설정은 유지하며, 메트로놈 화면과 mini panel에는 `소리`/`시각만`
  상태와 소리 크기가 보여야 한다.
- Android에서는 `소리 크기` slider가 tick 음량에 반영되는지 확인한다. iOS는 별도 native parity 전까지
  시스템 click fallback으로 보고 실기기에서 따로 기록한다.
- `소리 확인` 버튼으로 시작 전 tick이 들리는지 확인하고, 안 들리면 기기 볼륨/무음 모드/이어폰
  연결을 기록한다.
- 다중 선택 모드에서는 일반 목록뿐 아니라 `최근` quick access 악보 카드도 선택 상태로 바뀌어야 한다.
  선택된 카드는 check icon, primary border, 강조 배경이 보이고 viewer로 열리지 않아야 한다.
- 세트리스트 상세의 drag handle은 손가락으로 바로 잡을 수 있을 정도의 터치 영역으로 보이며, 위/아래
  버튼은 보조 이동 경로로 남아 있어야 한다.
- OCR, 실제 HID key capture wizard, SQLite/file-backed annotation migration, PDF 표준 annotation
  embed는 v1.1 이후 후속 범위다.
- cloud sync/account/server 저장은 없다.
