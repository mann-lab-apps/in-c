# 서비스 구조 검증 판단 매트릭스

작성일: 2026-08-19

## 목적

이 문서는 인터뷰와 2주 수동 매칭 결과가 들어왔을 때 `final-judgement.md`의 네 가지
최종 판단 중 하나로 빠르게 수렴하기 위한 기준이다.

중요한 원칙은 다음이다.

```text
좋은 말은 가설 신호이고, 반복 행동은 판단 근거다.
```

따라서 `좋겠다`, `있으면 쓸 것 같다`, `괜찮다`만으로는 최종 판단을 올리지 않는다.
클릭, 저장, 공유, 문의, 계속 수신 요청, 재등록 의향, 구체 금액처럼 행동에 가까운 반응이
있어야 한다.

## 최종 판단 조건

| 판단 | 필요한 증거 | 내려야 하는 결정 |
| --- | --- | --- |
| 이미 해결됨 | 인터뷰 다수가 Instagram, Obri, 예매처, 당근, 카톡방으로 충분하다고 말하고 수동 매칭 반응도 약함 | 이 방향은 낮춘다. 남길 기능이 있더라도 기존 앱의 작은 보조 기능으로 본다. |
| 문제는 있으나 플랫폼 구조 약함 | 불편은 반복되지만 공연, 레슨, 구인, 공고가 서로 다른 기준과 다른 참여자로 갈라짐 | 가장 강한 한 영역만 남기고 플랫폼 서사는 보류한다. |
| 알림/매칭 구조 가능성 있음 | 공급자가 올릴 이유가 있고, 수요자가 핏 맞는 알림을 허용하며, 수동 매칭에서 약한 행동이 반복됨 | 수동 매칭을 한 번 더 반복하고 최소 제품화 조건을 좁힌다. |
| 플랫폼 가능성 강함 | 공급 등록, 수요 알림 허용, 클릭/저장/문의, 공급자 재등록/유료 의향이 함께 반복됨 | 제품화를 검토하되, 자동화 범위는 수동 검증에서 반복된 부분만 만든다. |

## 증거 등급

| 등급 | 예시 | 판단에 쓰는 방식 |
| --- | --- | --- |
| A: 행동 증거 | 저장, 공유, 문의, 클릭, 계속 수신 요청, 재등록 요청, 구체 금액 제시 | 최종 판단의 주근거로 쓴다. |
| B: 경험 증거 | 최근 직접 겪은 missed info, 홍보 실패, 채널 선택 이유, 대체재 사용 경험 | 문제 반복성 판단에 쓴다. |
| C: 의견 증거 | 있으면 좋겠다, 쓸 것 같다, 재미있다, 필요해 보인다 | 다음 질문을 만드는 데만 쓰고 단독 근거로 쓰지 않는다. |
| D: 추정/해석 | 인터뷰어가 느낀 분위기, 예의상 긍정으로 보이는 답 | `unknown` 또는 `conditional`로 낮춘다. |

## 공급자 판단 규칙

`supplier-interviews.csv`에서 본다.

| 관찰 | 기록값 | 해석 |
| --- | --- | --- |
| 기존 채널만으로 충분하다고 함 | `would_register_again=no`, `skip_reason=not_needed` | `이미 해결됨` 쪽 근거 |
| 인스타/카톡방은 쉽지만 관계망 밖 도달이 약하다고 함 | `would_register_again=conditional/yes`, `skip_reason=time;dont_know_how;low_trust` | `알림/매칭 구조 가능성 있음` 쪽 근거 |
| Obri를 알고 쓰며 충분하다고 함 | `channels_used`에 Obri, `would_register_again=no` | 구인/레슨/프로필 영역 낮춤 |
| 결과 지표를 원하지만 유료 의향은 없음 | `wants_result_data=yes`, `wtp_range=0/under_10000` | 리포트 가치는 있으나 BM 약함 |
| 구체 금액을 말함 | `wtp_range=10000_30000` 이상 | 유료 가능성의 최소 근거 |
| 공개 부담이나 신뢰 조건이 큼 | `public_posting_concern=yes`, `needed_filter_or_trust_condition` 구체적 | 공개 플랫폼보다 승인/필터/반공개 구조 필요 |

공급자 쪽 pass는 아래를 모두 만족할 때만 강하게 본다.

- 5명 중 3명 이상 `would_register_again=yes/conditional`
- 1명 이상 `wtp_range=10000_30000` 이상
- `channel_reason` 또는 `skip_reason`에 기존 대체재의 구체적 한계가 있음

## 수요자 판단 규칙

`demand-interviews.csv`에서 본다.

| 관찰 | 기록값 | 해석 |
| --- | --- | --- |
| 찾아보면 충분하다고 함 | `push_acceptance=no`, `missed_relevant_info=no` | `이미 해결됨` 쪽 근거 |
| 놓친 적은 있지만 알림은 싫다고 함 | `missed_relevant_info=yes`, `push_acceptance=no` | 문제는 있으나 알림 해법 약함 |
| 핏이 맞으면 알림 허용 | `push_acceptance=yes/conditional` | 알림 가설 근거 |
| 실제 참여 여부와 별개로 정보 자체 유용 | `info_itself_useful=yes/conditional` | 핵심 문제정의 근거 |
| 한 달 허용 빈도가 매우 낮음 | `monthly_frequency_limit=0` 또는 사실상 1회 미만 | 알림 채널보다 검색/저장형이 적합 |
| 저장/공유/문의 기준을 구체적으로 말함 | `likely_action`에 `save/share/inquire/click` | 수동 매칭에서 추적할 행동 후보 |

수요자 쪽 pass는 아래를 모두 만족할 때 강하게 본다.

- 10명 중 5명 이상 `push_acceptance=yes/conditional`
- 10명 중 3명 이상 `keep_receiving_intent=yes/conditional`
- `fit_criteria`가 지역만이 아니라 악기, 수준, 목적, 장르, 작품 중 하나 이상으로 설명됨

## 수동 매칭 판단 규칙

`matching-participants.csv`와 `dispatch-log.csv`에서 본다.

| 관찰 | 해석 |
| --- | --- |
| 보냈지만 열람/답장도 거의 없음 | 말뿐인 관심 가능성 |
| 클릭만 있고 저장/공유/문의 없음 | 정보 탐색 가치는 있으나 강한 니즈는 약할 수 있음 |
| 저장/공유/문의가 2회 이상 반복 | 알림/매칭 구조 가능성 있음 |
| `continue_request=yes`가 반복 | 허락 기반 알림 관계 가능성 |
| `negative_reaction=bad_fit`이 반복 | 매칭 기준이 틀렸거나 관심 그래프 설명력이 약함 |
| `negative_reaction=too_many/annoying`이 반복 | 푸시 채널 부적합 또는 빈도 과다 |
| 공연/레슨/구인마다 참여자와 기준이 완전히 다름 | 플랫폼 구조 약함 |
| 같은 조건이 여러 유형에 작동 | 관심 그래프 가능성 |

약한 행동은 다음 중 하나다.

- `clicked=yes`
- `saved=yes`
- `shared=yes`
- `inquired=yes`
- `continue_request=yes`

단, `opened_or_replied=yes`만으로는 약한 행동으로 올리지 않는다.

## 관심 그래프 확인법

최소한 아래 질문에 답해야 한다.

| 질문 | 가능한 답 |
| --- | --- |
| 공연과 레슨이 같은 조건으로 매칭됐는가? | 예: 피아노 취미/송파/저녁 가능 |
| 레슨과 구인이 같은 조건으로 매칭됐는가? | 예: 바이올린 전공/서울/학생 지도 가능 |
| 공연과 구인이 같은 사람에게 의미 있었는가? | 예: 실내악 관심 전공자가 공연도 보고 대타 공고도 봄 |
| 유형마다 조건이 완전히 달랐는가? | 그렇다면 플랫폼 구조보다 단일 vertical에 가깝다 |

관심 그래프가 있다고 말하려면 `dispatch-log.csv`에서 서로 다른 2개 이상 `opportunity_code`
유형이 비슷한 `matching_reason`으로 약한 행동을 만든 사례가 있어야 한다.

예:

```text
M-004: 피아노 전공/서울/반주 관심
O-003 공연: 피아노 듀오 공연 클릭
O-008 구인: 교회 반주 공고 저장
```

이런 사례가 2명 이상 나오면 `cross_type_interest_graph`를 `weak` 이상으로 볼 수 있다.

## 판단을 낮춰야 하는 순간

아래 중 하나가 반복되면 아이디어를 좋게 해석하지 말고 판단을 낮춘다.

- 공급자는 올리고 싶어 하지만 수요자 반응이 없다.
- 수요자는 좋다고 말하지만 실제로는 열어보지 않는다.
- 공급자는 조회수나 감으로 충분하다고 말한다.
- 유료 의향이 전부 `0` 또는 `under_10000`이다.
- Obri, 인스타, 카톡방으로 충분하다는 말이 구체적 경험과 함께 반복된다.
- 수요자에게 `왜 나한테 보냈는지 모르겠다`가 2회 이상 나온다.
- 공연, 레슨, 구인의 매칭 기준이 서로 완전히 다르다.

## 최종 판단 작성 순서

1. `npm run validation:ops -- --write-scorecard`를 실행한다.
2. `scorecard.csv`에서 pass/fail/unknown을 옮긴다.
3. 공급자와 수요자에서 A/B 등급 증거만 먼저 뽑는다.
4. `substitute-positioning.md`의 버릴 영역/남길 영역과 대조한다.
5. 네 가지 판단 중 가장 보수적인 결론을 고른다.
6. 결론이 `알림/매칭 구조 가능성 있음` 이상이면, 어떤 조건에서만 그런지 쓴다.
7. 결론이 `이미 해결됨` 또는 `플랫폼 구조 약함`이면, 어떤 영역을 버릴지 먼저 쓴다.
