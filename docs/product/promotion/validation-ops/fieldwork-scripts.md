# 검증 필드워크 스크립트

작성일: 2026-08-19

## 목적

이 문서는 in C 서비스 구조 검증을 위해 실제 사람에게 보낼 섭외 문구와 인터뷰 진행
스크립트를 정리한다. 목표는 아이디어를 설득하는 것이 아니라, 현재 정보 유통 방식이
정말 반복 문제인지 확인하는 것이다.

## 말하지 않을 것

인터뷰 초반에는 아래 표현을 먼저 말하지 않는다. 듣는 사람이 좋은 답을 맞혀주기 쉬워진다.

- 클래식판 당근
- 맞춤형 공연 알림
- 연주자 홍보 플랫폼
- 우리가 해결하려는 문제
- 유료 홍보 상품
- 너라면 이 서비스 쓸 것 같아?

대신 실제 경험을 묻는다.

```text
최근에 음악 관련 정보를 어디에 올렸는지, 어디서 봤는지, 놓친 적이 있는지 궁금해.
```

## 공통 안내 문구

```text
요즘 클래식/음악 활동 정보가 어디서 어떻게 오가는지 작게 검증하고 있어요.
20분 정도 최근 경험을 여쭤보고 싶습니다.

답변은 익명 요약으로만 정리하고, 실명/연락처/단체방 이름/미공개 정보는 기록하지
않겠습니다. 불편한 질문은 넘어가도 됩니다.
```

## 공급자 섭외 문구

대상: 최근 6개월 안에 공연, 레슨, 구인, 마스터클래스, 콩쿠르, 공고 중 하나를 직접
홍보하거나 공유한 사람.

```text
최근에 공연/레슨/구인 같은 음악 관련 정보를 올리거나 홍보한 경험이 있으면 20분 정도
얘기 들어볼 수 있을까요?

어디에 올렸는지, 왜 그 채널을 썼는지, 더 하고 싶었지만 못 한 홍보가 있었는지 정도를
묻고 싶어요. 서비스 소개나 영업은 아니고, 지금 정보가 어떻게 흘러가는지 확인하는
단계입니다.
```

짧은 버전:

```text
최근 공연/레슨/구인 홍보해본 경험 관련해서 15-20분만 물어봐도 될까요?
어디에 올렸고 뭐가 아쉬웠는지 익명으로 정리하려고 해요.
```

## 수요자 섭외 문구

대상: 클래식 관객, 취미 음악인, 전공자, 레슨 관심자, 음악 기회 정보를 가끔 보는 사람.

```text
클래식/음악 관련 정보를 평소 어디서 접하는지 15-20분 정도 물어봐도 될까요?

공연, 레슨, 구인, 마스터클래스 같은 정보가 나에게 맞을 때 유용한지 보려는 작은
검증입니다. 실제 참여 여부보다 "알려주는 것 자체가 도움이 되는지"가 궁금해요.
```

짧은 버전:

```text
공연/레슨/음악 기회 정보를 어디서 보는지 15분만 물어봐도 될까요?
나한테 맞는 정보면 알림이 유용한지도 같이 확인해보고 있어요.
```

## 수동 매칭 참여 요청

대상: 2주 동안 맞는 정보만 1-3회 받아볼 사람.

```text
2주 동안 네 관심 조건에 맞는 음악 정보를 찾으면 아주 가끔 보내보려고 해.
공연에 꼭 가라는 뜻은 아니고, "이런 정보가 맞게 오면 유용한지"만 보고 싶어.

원하면 언제든 그만 보내달라고 해도 되고, 한 달 기준 몇 번까지 괜찮은지도 먼저 맞출게.
```

관심 조건 수집:

```text
1. 관심 있는 악기나 장르가 있어?
2. 이동 가능한 지역은 어디까지야?
3. 공연, 레슨, 구인, 콩쿠르/마스터클래스 중 뭐가 제일 관심 있어?
4. 가격이나 시간대에서 피하고 싶은 조건이 있어?
5. 한 달에 몇 번까지 이런 정보를 받아도 괜찮아?
```

## 공급자 인터뷰 진행

처음 5분은 설명보다 최근 사례를 하나 고르게 한다.

```text
최근에 직접 홍보하거나 공유했던 음악 관련 정보 하나를 떠올려주세요.
공연, 레슨, 구인, 공고, 마스터클래스 중 아무거나 괜찮습니다.
```

질문 순서:

1. 무엇을 홍보하거나 공유했나요?
2. 어디에 올렸나요?
3. 왜 그 채널을 선택했나요?
4. 인스타그램, 카톡방, 학과/선후배, 예매처, 당근, 커뮤니티 중 실제로 쓴 것은 무엇인가요?
5. 더 해보고 싶었지만 못 한 홍보가 있었나요?
6. 못 했다면 시간, 비용, 방법 모름, 효과 불신, 귀찮음, 민망함 중 무엇에 가까웠나요?
7. 유료 광고를 고려하거나 써본 적이 있나요?
8. 직접 세팅할 수 있다고 느꼈나요, 아니면 누가 대신 해주면 좋겠다고 느꼈나요?
9. 결과가 어땠는지 숫자나 피드백으로 알 수 있었나요?
10. 공개적으로 올리기 꺼려지는 정보가 있었나요?
11. 어떤 인증, 필터, 공개 범위가 있으면 더 올릴 수 있을까요?
12. 다음에도 이런 공간이 있으면 올릴 만한가요?
13. 무료가 아니라면 어떤 결과에 돈을 낼 수 있나요?

마지막 유료 질문은 실제 숫자로 묻는다.

```text
다음에 같은 방식으로 관련 있는 사람에게 보내주고 결과를 정리해준다면,
현실적으로 얼마까지는 부담 없이 맡길 수 있을까요?
```

## 수요자 인터뷰 진행

처음에는 앱이나 서비스 설명을 하지 않고 최근 정보 탐색 경험을 묻는다.

```text
최근에 공연, 레슨, 구인, 마스터클래스 같은 음악 관련 정보를 본 적이 있나요?
어디서 봤나요?
```

질문 순서:

1. 음악 관련 정보는 평소 어디서 얻나요?
2. 관심 있었을 법한 정보를 뒤늦게 알게 된 적이 있나요?
3. 어떤 조건이면 나에게 맞는 정보라고 느끼나요?
4. 악기, 지역, 날짜, 가격, 수준, 작품, 연주자, 목적 중 무엇이 가장 중요하나요?
5. 정말 핏이 맞는 정보라면 푸시나 DM을 받아도 괜찮나요?
6. 한 달에 몇 번까지 괜찮나요?
7. 실제로 가지 않더라도 정보 자체가 유용할 수 있나요?
8. 어떤 경우에 저장, 공유, 문의, 링크 클릭을 할 것 같나요?
9. 어떤 정보는 왜 나한테 보냈는지 모르겠다고 느낄 것 같나요?
10. 어떤 조건이면 바로 그만 받고 싶을 것 같나요?

푸시 질문은 아래처럼 확인한다.

```text
핵심은 "보낼 때마다 가느냐"가 아니라, 가고 말고는 네가 정하더라도 정말 맞는 정보를
알려주는 것 자체가 유용한지야. 이 기준으로 보면 어때?
```

## Instagram Insights 요청 문구

```text
가능하면 최근 공연 홍보 게시물의 인사이트 숫자를 익명으로만 봐도 될까요?
캡처 원본이나 계정명은 저장하지 않고, accounts reached, follower/non-follower reach,
save, share, profile visit, link click 정도의 숫자만 범위로 기록하려고 합니다.
```

확인할 숫자:

- accounts reached
- follower reach
- non-follower reach
- profile visits
- link clicks 또는 profile link taps
- saves
- shares
- comments
- DMs/inquiries

## 발송 후 후속 질문

정보를 보낸 뒤 24-72시간 안에 짧게 묻는다.

```text
어제 보낸 정보는 네 조건에 맞는 편이었어?
계속 이런 식으로 보내도 괜찮은지, 아니면 왜 보냈는지 모르겠는지도 편하게 말해줘.
```

행동 확인:

```text
혹시 링크를 열어봤거나, 저장/공유/문의할 생각이 들었는지만 체크해도 될까?
실제로 갔는지는 중요하지 않고, 정보 자체가 쓸모 있었는지가 궁금해.
```

## 공급자 결과 공유 후 질문

수동 매칭이나 작은 홍보가 끝난 뒤 묻는다.

```text
이번에는 몇 명에게 어떤 기준으로 보냈고, 확인 가능한 반응은 이 정도였습니다.
이 결과를 보면 다음에도 이런 방식으로 올려볼 만하다고 느끼나요?
```

이어 묻는다.

- 가장 유용했던 부분은 무엇인가요?
- 기대와 달랐던 부분은 무엇인가요?
- 더 보고 싶은 숫자나 피드백이 있나요?
- 다음에도 다시 등록하고 싶은가요?
- 돈을 낸다면 노출, 클릭, 문의, 대신 실행, 결과 리포트 중 어디에 낼 수 있나요?
- 부담 없는 금액은 어느 정도인가요?

## 기록 직후 할 일

인터뷰가 끝나면 10분 안에 아래 파일 중 하나를 채운다.

- 공급자 인터뷰: `supplier-interviews.csv`
- 수요자 인터뷰: `demand-interviews.csv`
- 수동 매칭 참여자: `matching-participants.csv`
- 공급 정보: `opportunity-inventory.csv`
- 발송 결과: `dispatch-log.csv`

기록할 때 주의:

- 답변이 좋은 쪽으로 들렸어도 행동 근거가 없으면 `conditional`로 둔다.
- "오 좋네"만으로는 성공 신호로 올리지 않는다.
- `계속 보내줘`, `저장했다`, `친구에게 공유했다`, `문의했다`, `다음에도 올리고 싶다`,
  `얼마까지 가능하다`를 강한 신호로 본다.
- 부정 반응은 실패가 아니라 매칭 기준을 고치는 데이터로 기록한다.
