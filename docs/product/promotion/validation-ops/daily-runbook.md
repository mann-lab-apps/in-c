# 2주 검증 일일 실행 체크리스트

작성일: 2026-08-19

## 목적

이 문서는 in C 서비스 구조 검증을 매일 실제로 굴리기 위한 체크리스트다. 핵심은 앱을
더 만들지 않고, 사람이 직접 정보 흐름을 흉내 내면서 반복되는 신호를 모으는 것이다.

## 매일 시작할 때

- 오늘 연락할 공급자 후보 2명과 수요자 후보 3명을 고른다.
- `recruiting-tracker.csv`에서 `next_action`이 비어 있지 않은 행을 먼저 본다.
- 전날 인터뷰나 발송 기록이 CSV에 반영됐는지 확인한다.
- 오늘 보낼 음악 기회 정보가 정말 특정 사람에게 맞는지 한 줄로 설명한다.
- 맞는 이유를 설명할 수 없으면 보내지 않는다.

## Day 1-2: 후보 정리

목표:

- 공급자 후보 10명
- 수요자 후보 15명
- 공개 공급 정보 후보 9개 이상

기록:

- `recruiting-tracker.csv`
- `opportunity-inventory.csv`

완료 기준:

- 공급자 5명에게 연락할 수 있는 후보 풀이 있다.
- 수요자 10명 인터뷰와 15명 수동 매칭 후보 풀이 있다.
- 공연, 레슨, 구인 정보가 각각 최소 3개씩 후보로 있다.

## Day 3-5: 공급자 인터뷰

목표:

- 공급자 인터뷰 5명
- 가능하면 Instagram Insights 3명
- Obri, Instagram, 예매처, 카톡방 사용 여부 확인

기록:

- `supplier-interviews.csv`
- `recruiting-tracker.csv`

인터뷰 직후 확인:

- 최근 홍보 대상이 무엇이었는가?
- 기존 대체재로 충분했는가?
- 더 하고 싶었지만 못 한 일이 있었는가?
- 다시 올릴 의향이 있는가?
- 돈을 낸다면 무엇에 낼 수 있는가?

## Day 3-7: 수요자 인터뷰

목표:

- 수요자 인터뷰 10명
- 수동 매칭 참여 동의 15명 중 일부 확보

기록:

- `demand-interviews.csv`
- `matching-participants.csv`
- `recruiting-tracker.csv`

인터뷰 직후 확인:

- 어디서 음악 정보를 얻는가?
- 맞는 정보를 놓친 경험이 있는가?
- 핏 맞는 정보라면 푸시/DM을 허용하는가?
- 한 달 몇 번까지 괜찮은가?
- 저장, 공유, 문의, 클릭을 할 기준은 무엇인가?

## Day 6-10: 공급 정보 확정

목표:

- 공연 3개
- 레슨 3개
- 구인/반주/대타 3개

기록:

- `opportunity-inventory.csv`

완료 기준:

- 각 정보의 공개 범위가 명확하다.
- 링크 또는 문의 경로가 있다.
- 누구에게 보낼지 매칭 가설이 한 줄로 적혀 있다.
- 민감한 정보는 `semi_private`로 표시되어 있다.

## Day 8-14: 수동 매칭 발송

목표:

- 허락받은 사람에게만 보낸다.
- 한 사람에게 너무 많이 보내지 않는다.
- 발송마다 매칭 이유를 한 줄로 기록한다.

기록:

- `dispatch-log.csv`

발송 직후 기록:

- 보낸 날짜
- 수신자 코드
- 정보 코드
- 매칭 이유
- 채널
- 메시지 버전

24-72시간 후 기록:

- 열람/답장
- 클릭
- 저장
- 공유
- 문의
- 계속 보내달라는 반응
- 부정 반응

## Day 14: 집계와 판단

명령:

```bash
npm run validation:ops -- --write-scorecard
```

기록:

- `scorecard.csv`
- `final-judgement.md`

판단 순서:

1. 기존 대체재로 충분한 영역을 먼저 버린다.
2. 공급자 의향과 수요자 알림 수용을 분리해서 본다.
3. 말이 아니라 클릭, 저장, 공유, 문의, 계속 수신 요청을 본다.
4. 공연, 레슨, 구인이 같은 관심 기준으로 묶이는지 확인한다.
5. 네 가지 최종 판단 중 하나만 고른다.

## 오늘의 최소 진전

하루가 정신없이 지나갈 때는 아래 중 하나만 해도 된다.

- 공급자 후보 1명에게 섭외 메시지 보내기
- 수요자 후보 1명에게 섭외 메시지 보내기
- 공개 공급 정보 1개를 `opportunity-inventory.csv`에 추가하기
- 발송 후 후속 질문 1개 보내기
- 인터뷰 메모 1개를 익명 CSV로 정리하기

## 하지 않을 것

- 인터뷰 전 새 기능 만들기
- 좋은 반응을 얻으려고 설명을 길게 하기
- 무리하게 아무에게나 정보 보내기
- 예의상 반응을 성공 신호로 올리기
- 실명, 연락처, 단체방 원문을 레포에 남기기
