# in C 서비스 구조 수동 검증 워크북

작성일: 2026-08-19

## 목적

이 문서는 in C의 서비스 구조가 실제로 성립하는지 제품 없이 확인하기 위한 실행
워크북이다. 검증 대상은 "공연 하나를 보면 바로 예매하는가"가 아니라 다음 질문이다.

```text
클래식/음악 기회 정보가 정말 맞는 사람에게만 전달될 때, 받는 사람은 알림 자체를
유용하게 느끼고 공급자는 다시 올릴 이유를 느끼는가?
```

따라서 이번 단계에서는 앱, 커뮤니티, 광고 대시보드, 프로필 관리, 레슨 관리 기능을
만들지 않는다. 사람이 직접 정보를 모으고, 조건을 받고, 맞는 정보만 보내고, 반응을
기록한다.

## 검증할 서비스 구조

공급 정보:

- 연주회 홍보
- 연주자/반주자/대타 구인
- 레슨 홍보
- 콩쿠르, 마스터클래스, 오디션, 공고
- 향후 프로필/활동 이력, 레슨 관리, 반응 데이터

수요:

- 내게 맞는 연주회 정보
- 더 전문화된 레슨 선택지
- 연주자 구인, 마스터클래스, 콩쿠르, 공고 발견
- 클래식 생태계가 어떻게 굴러가는지 이해하는 맥락

핵심은 공연, 레슨, 구인, 공고가 각각 다른 서비스처럼 갈라지는지, 아니면 악기, 지역,
수준, 관심, 목적 기반의 같은 관심 그래프 위에서 흐를 수 있는지 확인하는 것이다.

## 개인정보 원칙

- 실명, 전화번호, 이메일, 카카오톡 ID, 인스타그램 ID, 미공개 홍보비, 단체 채팅 원문은
  레포에 기록하지 않는다.
- 레포에는 익명 코드, 대상군, 요약 인사이트, 지표만 남긴다.
- 원문 인용은 당사자 동의를 받은 경우에만 익명으로 사용한다.
- Instagram Insights 캡처는 원본을 공개 레포에 넣지 않고 수치만 익명 집계한다.
- 공개적으로 올리기 민감한 구인/레슨 정보는 반공개 유통 조건을 따로 기록한다.

## 이번 검증의 성공 기준

이번 검증은 2주 안에 완벽한 PMF를 증명하려는 것이 아니다. 다음 신호가 반복되면
`수동 매칭을 더 반복할 이유가 있다`고 본다.

| 항목 | 성공 신호 | 실패 신호 |
| --- | --- | --- |
| 공급자 의향 | 5명 중 3명 이상이 이런 공간이 있으면 올릴 만하다고 말함 | 기존 인스타/카톡/예매처로 충분하다는 답이 우세 |
| 수요자 알림 수용 | 10명 중 5명 이상이 핏이 맞으면 알림이 유용하다고 말함 | 음악 정보 푸시 자체를 부담스럽게 여김 |
| 지속 수신 허용 | 10명 중 3명 이상이 한 달 몇 회 수준으로 계속 받아도 된다고 말함 | 관심은 있지만 알림은 원하지 않음 |
| 약한 반응 | 저장, 공유, 문의, 클릭 중 하나 이상이 반복됨 | 말로는 관심 있지만 행동이 없음 |
| 공급자 반복 | 다음에도 올리고 싶다거나 돈을 낼 수 있다는 구체 답변이 나옴 | 고마운 도움으로만 받아들이고 재등록 의향이 약함 |
| 관심 그래프 | 공연/레슨/구인이 일부 같은 조건으로 매칭됨 | 각 영역이 완전히 다른 서비스처럼 갈라짐 |

## 2주 미션을 쉽게 풀어 쓰기

```text
2주 동안 앱을 만들지 말고, 사람이 in C처럼 행동해본다.
```

해야 할 일은 세 가지다.

1. 음악 기회 정보를 9개 모은다.
2. 받을 사람 15명에게 관심 조건을 묻는다.
3. 정말 맞는 정보만 보내고, "이런 건 계속 보내줘"라는 반응이 생기는지 본다.

좋은 결과는 티켓 판매 보장이 아니다. 좋은 결과는 정보가 맞게 갔을 때 클릭, 저장, 공유,
문의, 재등록 의향 같은 작은 행동이 반복되는 것이다.

## 최종 판단 옵션

| 판단 | 의미 | 다음 행동 |
| --- | --- | --- |
| 이미 해결됨 | 인스타, 당근, 카톡방, 예매처, 커뮤니티로 충분하다 | 이 방향의 우선순위를 낮춘다 |
| 문제는 있으나 플랫폼 구조 약함 | 불편은 있지만 공연/레슨/구인이 하나로 묶이지 않는다 | 가장 강한 한 영역만 남긴다 |
| 알림/매칭 구조 가능성 있음 | 수요자가 핏 맞는 알림을 원하고 공급자도 올릴 이유가 있다 | 수동 매칭을 한 번 더 반복한다 |
| 플랫폼 가능성 강함 | 등록, 알림, 반응, 재등록/유료 의향이 반복된다 | 최소 제품화를 검토한다 |

### 공급자 질문

```text
최근 공연/레슨/구인/공고는 어디에 올렸나요?
```

- 왜 그 채널을 썼나요?
- 인스타그램, 카톡방, 학과/선후배 관계망, 당근, 예매처, 커뮤니티 중 실제로 무엇을
  사용했나요?
- 더 넓게 알리고 싶었지만 못 한 적이 있나요?
- 못 했다면 시간 부족, 비용 부담, 방법 모름, 효과 불신, 귀찮음, 민망함 중 무엇에
  가까웠나요?
- 유료 광고를 고려하거나 써본 적이 있나요?
- Meta/Instagram, 당근, 네이버, 카카오 광고를 직접 세팅할 수 있다고 느꼈나요?
- 공개적으로 올리기 꺼려지는 정보가 있나요?
- 어떤 필터, 인증, 공개 범위가 있으면 올릴 수 있나요?
- 결과를 숫자나 피드백으로 받고 싶나요?
- 돈을 낸다면 노출, 클릭, 문의, 대신 실행, 결과 리포트 중 무엇에 낼 수 있나요?

## 매칭 판단 기준

정보를 보내기 전, 왜 이 사람에게 보낼 만한지 한 줄로 설명할 수 있어야 한다.

| 기준 | 설명 | 예시 |
| --- | --- | --- |
| 악기/장르 | 관심 악기, 전공, 취미 활동과 맞음 | 피아노 취미생에게 피아노 독주회 |
| 지역/거리 | 실제 이동 가능한 범위 | 서울 서북권 거주자에게 마포/서대문 공연 |
| 날짜/생활 리듬 | 참여 가능한 시간대 | 평일 저녁 가능자에게 저녁 공연 |
| 수준 | 입문, 취미, 전공, 프로 수준이 맞음 | 전공자에게 마스터클래스/대타 구인 |
| 목적 | 감상, 배움, 일거리, 네트워크 중 목적이 맞음 | 레슨 관심자에게 선생님 프로필 |
| 맥락 | 작품, 연주자, 장소, 가격을 이해할 이유가 있음 | 좋아하는 작곡가 프로그램 |

보내지 않는 기준:

- 설명 가능한 매칭 이유가 없다.
- 단지 음악을 좋아한다는 이유만 있다.
- 공급자 부탁 때문에 무리해서 보낸다.
- 같은 사람에게 한 달 허용 빈도를 넘긴다.
- 공개 범위가 맞지 않는다.

## 반응 해석

| 반응 | 강도 | 해석 |
| --- | --- | --- |
| 읽음 없음 | 약한 실패 | 채널, 관계, 메시지 길이 문제일 수 있음 |
| 읽었지만 무반응 | 중립/약한 실패 | 정보는 봤지만 행동할 만큼 맞지 않았을 수 있음 |
| 고마워/괜찮네 | 약한 관심 | 예의 반응과 구분 필요 |
| 저장 | 의미 있는 약한 반응 | 지금 행동하지 않아도 정보 가치 있음 |
| 공유 | 강한 신호 | 다른 relevant audience로 확산 가능성 |
| 문의 | 매우 강한 신호 | 공급자 가치와 직접 연결 |
| 링크 클릭 | 의미 있는 행동 | 카피/타깃/링크 품질 검토 가능 |
| 계속 보내줘 | 핵심 신호 | 푸시/알림 가설의 직접 근거 |
| 왜 보냈는지 모르겠음 | 중요한 실패 | 매칭 기준이 틀렸거나 설명이 부족함 |
| 이런 알림은 싫음 | 강한 실패 | 빈도/채널/허락 문제 재검토 |
