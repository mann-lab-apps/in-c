# 피아노 연주 엔진 고도화 목표모드 프롬프트

작성일: 2026-10-26

```text
목표: 짧은 피아노 악보를 입력해 기본 재생과 모델 적용 재생을 사보앱에서 비교할 수 있는 개발용 데모를 구현한다.

현재 상태:
- experiments/piano-performance에 PyTorch 환경과 dummy 학습이 있다.
- 실제 MusicXML/MIDI 파싱, 학습 checkpoint, 추론, 사보앱 연결은 구현이 필요하다.
- IMSLP 후보 메타데이터는 실제 학습 데이터 또는 권리 확정 자료가 아니다.

작업 범위:
1. 기존 코드를 읽고 사용자 변경을 보존한다.
2. 검증된 라이브러리로 MusicXML/score MIDI/performance MIDI를 읽는다.
3. 음높이와 시간 범위를 사용해 짧은 구간을 정렬한다. 누락음과 추가음을 보고하며 다른 음높이를 임의 매칭하지 않는다.
4. 실제 파일을 사용하는 supervised 학습 명령을 만든다.
   - 타이밍과 velocity 단위를 정규화한다.
   - 학습/검증 작품을 분리하고 평균 예측 baseline과 비교한다.
   - checkpoint, config, 데이터 출처, metrics를 저장한다.
5. checkpoint를 별도 명령에서 다시 읽고 새로운 악보를 추론한다.
   - 예측 JSON과 expressive MIDI를 출력한다.
   - timing/velocity 범위와 유효 숫자를 검사한다.
6. 사보앱에 개발용 옵션으로 비교 재생 패널을 연결한다.
   - 현재 악보의 note request를 내보낸다.
   - Python이 만든 예측 JSON을 불러온다.
   - 기본/모델 재생을 선택할 수 있다.
   - 다른 악보나 편집 전 악보의 예측은 거부한다.
   - 모드 전환 시 재생을 정지하고 다시 시작한다.
7. 자체 생성한 합성 fixture로 파일 파싱→정렬→학습→저장→재로딩→추론→앱 적용을 검증한다.

데이터 원칙:
- 이번 작업에서는 IMSLP 다운로드와 대량 크롤링을 하지 않는다.
- 외부 자료는 악보/연주 각각의 sidecar와 사용 검토 기록을 요구한다.
- 합성 데이터 결과를 실제 IMSLP 연주 학습 성과라고 표현하지 않는다.
- 모델 metadata와 앱 표시에서 synthetic/human-performance 출처를 유지한다.
- 실제 학습 데이터가 없으면 기술 데모를 완료하고 음악적 품질 검증은 미완료로 명시한다.

기술적 제한:
- 첫 버전은 일정한 기준 템포의 짧은 구간이다.
- 장식음, 반복 구조 차이, 큰 템포 편차, 오디오에서 MIDI 전사, 페달 예측은 후속 작업이다.
- 현재 앱의 음원 엔진을 유지한다. 이번 검증은 음색 개선이 아니라 timing/velocity 적용 검증이다.
- 기존 iOS 앱에는 기능을 추가하지 않는다. 영향이 생기면 AGENTS.md의 iOS metadata 절차를 따른다.

완료 조건:
- pytest, ruff, 관련 Vitest와 TypeScript 검사 통과.
- CPU에서 재현 가능한 파일 기반 학습/추론 데모 실행.
- checkpoint 재로딩 후 JSON과 MIDI 생성.
- 사보앱에서 예측 파일 불러오기와 기본/모델 전환 확인.
- 잘못된 악보, 잘못된 예측 범위, 학습/검증 누수 방지 테스트.
- 실행 명령과 현재 한계를 README에 기록.
- 실제 녹음 학습 여부와 UI 검증 범위를 정확히 보고.
```
