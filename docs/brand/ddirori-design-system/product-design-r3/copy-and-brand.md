# 문구·브랜드·샘플 정책

기존 [voice](../../ddirori-brand-system/voice.md)·[motion](../../ddirori-brand-system/motion.md)·[naming](../../ddirori-brand-system/naming.md)을 유지한다. UI는 중립 면과 명료한 행동에 집중한다. 제품군이 같은 이름·여백·정보 위계·상태 문구를 공유하되 모든 화면에 같은 환영 문장을 복제하지 않는다.

## 용어

| 용어 | 사용 의미 | 피할 오해 |
| --- | --- | --- |
| 파일 가져오기/추가 | 사용자가 선택한 파일을 앱이 읽고 지원 정책에 따라 사본/metadata 저장 | 클라우드 전체 동기화·원본 이동 |
| 작품 | Play의 작곡가·제목·작품번호 맥락 | Score 문서 ID와 같은 것으로 취급 |
| 녹음 | 한 작품의 연주/판본 맥락 | 파일 하나와 항상1:1이라고 가정 |
| 악장/트랙 | 녹음 안 재생 단위와 실제 매핑 | PDF 페이지와 대응한다고 가정 |
| 악보 | Score가 보관·열람하는 문서 | Studio 편집 모델까지 가진다고 가정 |
| 프로젝트 저장 | Studio .chromatics 편집 문서와 설정 저장 | PDF 출력·MusicXML 사본·복구본과 혼합 |
| 사본 내보내기 | 원본과 별도로 전달할 파일 결과 | 다른 앱 저장/수신 확인 |
| 연결 파일 | 사용자가 특정 Score 악보에 추가한 참고 파일/음원 사본 | 공유 계정의 자료·지속적인 원본 링크 |

## 주요 문구

| 상태 | 문구/행동 예시 | 실제 조건 |
| --- | --- | --- |
| Play 처음 | ‘내 음원을 가져와 볼까요?’ / ‘음원 파일 가져오기’ | 실제 초기 파일0 |
| Play 정리 전 | ‘가져온 음원을 작품과 녹음으로 정리해요.’ | 실제 보관 파일·catalog 미등록 |
| Score 처음 | ‘첫 악보를 펼쳐볼까요?’ / ‘PDF 악보 추가’ | 기존 자료·수신 결과 없음 |
| Studio 처음 | ‘새 악보를 만들어 볼까요?’ / ‘새 악보 만들기’ | 최근 파일/복구 경로는 함께 유지 |
| 분석 대기 | ‘파일은 보관했어요. 분석 결과는 아직 준비 중이에요.’ | 복사 성공·analysisPending |
| 부분 결과 | ‘가져옴1개 · 실패1개’ + 실제 실패 목록/재시도 | 각 파일 결과 분리 |
| 접근 실패 | ‘이 파일을 읽을 수 없어요. 접근 가능한 사본을 선택해 주세요.’ | 원인에 맞춤. 일반 권한 거부와 구분 |
| 저장 실패 | ‘변경 사항을 저장하지 못했어요.’ + 유지 범위/재시도 | 실제 실패, 저장됐다고 보장하지 않음 |
| PDF 후속 | ‘PDF로 연습 이어가기’ / ‘가져오는 방법’ | 실제 PDF 결과 존재, 수동 안내 |
| 음원 후속 | ‘이 음원으로 악보 연습하기’ / ‘연결하는 방법’ | 실제 내보낼 관리 파일과 지원 형식 |
| 설치 미확인 | ‘이 기기에서 앱을 열 수 있는지 확인하지 못했어요.’ | host가 설치 여부 확인 못함 |
| 첫 성취 | ‘첫 음악을 재생했어요.’ / ‘첫 연습 표시를 남겼어요.’ / ‘첫 악보를 파일로 저장했어요.’ | 각 실제 완료 callback 이후, 테스트·샘플 구분 |

작업 결과는 실제 원인을 우선한다. 시스템 문구를 모두 ‘바흐의 대사’로 쓰지 않는다. 개인 파일의 절대경로·진단 원문은 기본 메시지에 넣지 않는다. ‘알아서 연결’, ‘완벽히 동기화’, ‘설치 완료’처럼 지원되지 않는 상태를 만들지 않는다.

## 바흐와 모션

환영의 빈 상태에서 단순한 놀란 바흐, 첫 성취에 작은 기쁜 바흐48 정도를 선택적으로 사용한다. 실제 악보/재생 도구·권한/오류/파괴적 확인에는 반복 배치하지 않는다. R3에서는 작업 영역 밖의 검토 설명과 제품 피드백을 구분했다.

미상 진행은 현재 음형 Progress·작업명, 실제 진행률은 engine 제공 값. 1:1:3 리듬은 기존 음형 opacity 모션에만 사용한다. 작업 대기 시간을 브랜드 연출 때문에 늘리지 않는다. reduced-motion은 반복 움직임 제거·상태 유지. 자동 효과음/햅틱/축포 없음.

## 샘플·fixture

- Play는 현재 ENABLE_DEMO_LIBRARY 경계를 유지하고 사용자 초기 라이브러리에 데모를 자동 생성하지 않는다.
- Score는 사용자가 PDF/이미지를 추가하는 흐름을 우선한다. 제품 샘플 제공은 실제 앱 bundle·권리·삭제/복사 정책이 확인된 별도 opt-in 후속이다.
- Studio의 빈 기본 악보는 생성할 새 문서이며 공개 음악 샘플이 아니다. 기존 fixture query를 일반 사용자의 예제로 자동 노출하지 않는다.
- R3의 PDF는 저장소가 직접 생성한 `short-score.pdf`의 기존 R2 raster를 재사용했다. 생성 출처와 해시는 asset-provenance에 기록한다. 오디오 파일은 가상 표시명이고 실제 소리 자산이 없다. 작곡가·작품명은 검토용 입력 예제다.
- 샘플을 나중에 제공한다면 명시적 선택·출처/권리·사용자 파일과 분리·삭제·재생성 정책을 정하고 샘플 성공을 사용자 실제 자료의 첫 성취로 세지 않는다.
