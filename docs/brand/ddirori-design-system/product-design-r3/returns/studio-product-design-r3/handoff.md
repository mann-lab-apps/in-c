## Actual Execution

`scripts/verify-studio-first-use.cjs` loads the **production renderer and production preload**, with isolated userData and QA IPC handlers replacing OS dialogs/file destinations. It writes real temporary project/recovery files and real export-scene PDF bytes, not an in-product fake task. It does not claim to validate production chooser permission or atomic file-service policy; existing main file-service unit tests are included in the product suite.

Sequence: start -> full wizard -> Enter submit -> N/C actual score input -> undo/redo -> save cancel -> injected save failure -> pending disk save -> first success -> actual disk reopen -> D edit -> PDF cancel/fail/success -> manual guide/Escape focus -> actual recovery reload/open -> MusicXML output.

- `first.chromatics`: actual serialized score with one C note after undo/redo. Reopened through production preload and native decoder.
- `practice.pdf`: actual current App print scene after a later D edit. A4, one page, rasterized and directly reviewed. It is not a three-page Score receipt test.
- `first.musicxml`: actual serializer output after native recovery; contains the later D note.
- `recovery.json`: actual App autosave payload via production preload to an isolated QA store.
- Native project score is unchanged by the later PDF output; header remains dirty. Actual Score receipt is **not verified**.

QA error logs intentionally include `R3 disk unavailable` and `R3 PDF unavailable`; these are controlled failure cases followed by retry, not a failed final run. The QA reload explicitly confirms its own dirty-document unload to test recovery. It does not alter the product's beforeunload guard or another app window.
