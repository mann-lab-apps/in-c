# 사용자 관찰 계획 · 미실행

실제 사용자 테스트를 진행하지 않았다. 아래는 모집·실행할 때 사용할 질문과 과제다. 선호도·완료율·시간·사용자 발언은 현재 결과로 기록하지 않는다.

## 확인하려는 질문

1. Play의 ‘파일 가져오기’와 ‘작품·녹음 정리’를 다른 단계로 이해하는가? 복잡한 catalog 용어 때문에 첫 재생을 포기하는가?
2. Score에서 PDF 추가 완료와 지면 준비·주석 저장 완료를 구분하는가? 주석보다 읽기/연습을 먼저 선택하는 사용자의 길도 자연스러운가?
3. Studio의 프로젝트 저장과 PDF 사본 내보내기 차이가 이해되는가? 생성 설정이 첫 입력을 과하게 늦추는가?
4. 두 연결이 실제로 필요해지는 순간은 언제인가? 제품군 안내가 작업을 방해하는가?
5. 수동 파일 전달 안내를 보고 자동 동기화/직접 앱 이동을 기대하는가? 어떤 파일과 대상 악보를 선택하는지 아는가?
6. 취소·부분 실패·앱 미설치에서 완료한 자료가 남아 있다는 사실을 발견하는가?

## 관찰 과제

| 대상 | 안내할 목적 | 관찰할 것 |
| --- | --- | --- |
| Play 신규 | ‘가지고 있는 이 음원을 듣고 싶어요.’ | 첫 행동·정리 단계 발견, 필수 정보 부담, 첫 재생과 가져오기 구분 |
| Score 신규 | ‘이 PDF에 다음 연습 위치를 표시해 주세요.’ | 지면 진입·주석 도구·저장 상태 이해, 페이지 보존 |
| Studio 신규 | ‘짧은 악보를 만들고 다음에 다시 편집할 수 있게 남겨 주세요.’ | 실제 입력·프로젝트 형식 선택, PDF와 혼동 |
| J01 | ‘컴퓨터에서 만든 악보를 태블릿에서 연습해 주세요.’ | 기기 간 전달 인지, 원본/사본 이해, 실패 후 복구 |
| J02 | ‘이 녹음을 들으며 이 악보를 연습하고 싶어요.’ | 대상 악보 선택·음원 내보내기/연결, 자동 동기화 기대 |
| 재방문 | ‘어제 하던 작업을 이어가 주세요.’ | 불필요한 안내 반복·최근/복구/lastPage 접근 |

처음에는 버튼 이름을 알려주지 않고 목적만 제시한다. 막힌 뒤에는 원인·기대 위치·다음 행동을 질문한다. 설계에서 기대한 클릭 경로와 다르다는 이유만으로 실패로 처리하지 않는다.

## 실행 순서와 기록

디자인 시안은 용어·발견성·흐름 비교에 사용한다. 실제 chooser·다른 기기 전달·codec·PDF 필기·저장 복구는 구현된 제품으로 별도 관찰한다. 처음 사용하는 음악 애호가와 악보/사보 경험자를 구분해 기록하며 작은 표본의 의견을 전체 사용자의 비율로 확대하지 않는다.

동의받은 범위에서 task 성공/도움 필요/중단·잘못 이해한 상태·다음 행동 기대를 기록한다. 개인 파일 대신 권리가 확인된 과제 자료를 제공하고 음원·악보·경로 원문을 분석 로그로 수집하지 않는다.

남은 선택: Play 정리 단계의 최소 노출량, 첫 성취 피드백의 표시 빈도, Studio PDF 후속 안내의 위치, J02의 실제 사용 빈도, 미설치 안내의 효용. 사용자 결과를 받으면 문구/순서/노출 조건을 조정한다. 대표색·아이콘 선택 테스트와 이번 여정 테스트는 별도로 판단한다.
