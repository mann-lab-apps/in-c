# 띠로리 디자인 시스템 고도화

> 이전 실험 기록. 현재 색상·검증은 [중립 색상 시스템](color-system.md)을 따른다. 아래 라임 시안의 미감은 승인되지 않았다.

2026-10-23 · 로컬 권고안 · 최종 브랜드 승인 전

## 선택과 의미

라임 `#D5ED70`을 대표색, 짙은 올리브 `#52651A`를 밝은 화면의 행동색으로 권고한다. 대표색 위에는 잉크 `#263125`를 사용한다. 바흐의 흰 가발과 살구색 얼굴을 보존하며 밝은 중립 바탕 `#FAFAF6`을 넓게 쓴다.

Wise에서 참고한 것은 사용자 에너지와 탐험을 표현하는 방식이다. 띠로리의 라임은 ‘낯선 음악으로 한 걸음 더’라는 우리의 해석이다. 공식 Wise 색상값을 복제하거나 음악의 보편적인 색으로 주장하지 않는다. 카카오·네이버에서는 제품군 연결, 당근에서는 간결함과 일관성의 원리를 취한다.

동일 화면의 코럴은 온기가 좋지만 오류색·피부색과 가까우며, 노랑은 표정과 잘 맞지만 국내 카카오 연상이 강해질 가능성이 있다. 기존 파랑은 읽기 쉽지만 이번 탐색에서 원하는 활력과 구별점을 라임이 더 잘 드러낸다고 판단했다. 이는 내부 시각 판단이며 사용자 식별 시험 결과는 아니다.

대표색과 행동색의 분리는 장시간 작업 면에 밝은 라임을 과다하게 사용하지 않으면서 앱 런처와 소개 영역에 기억할 색을 주기 위한 선택이다. 앱별 색 분화보다 기능 실루엣을 우선한다.

## 구현 감사와 결정

| 영역 | 확인한 구현 | 결정 |

| 색 | UI 토큰은 공유하나 제작 Python·Android 배경·바흐 painter에 고정색 존재 | 선택 팔레트 입력을 분리하고 자산·네이티브에 연결 |
| 글자·간격 | 긴 제목 줄바꿈, 4~32 간격, touch 48/desktop compact 32 제공 | 유지. 제품 글꼴 교체 없이 검증 |

| 버튼·검색·선택 | callback 기반, 비동기 중복 실행 차단, 외부 query 제어 | 유지. 상태별 색을 새 팔레트에 연결 |

## 소유 원본과 재생성

- `palette-candidates.json`: 라임·코럴·노랑·기존 파랑 비교 입력
- `palette-pilot.json`: 현재 선택한 로컬 시범 팔레트
- `tokens.json`: 역할 alias·간격·모서리·밀도·모션
- `../ddirori-visuals/palette.json`: 이전 파랑 선택 이력. 새 UI 입력이 아님
- `../ddirori-brand-system/tools/build.py`: 승인 음형·제품 실루엣·바흐·워드마크 제작
- `packages/ddirori_web/catalog/palette-comparison.tsx`: 실제 공통 React 컴포넌트로 만든 비교 화면

`brand/onBrand`와 `action/onAction`을 분리했다. 기존 `sky/peach` 키는 API 호환성을 위해 유지하며 sky는 이제 보조 면 역할이다. 다크에서는 밝은 라임 행동색과 짙은 글자를 쓴다. 성공·주의·오류와 악보 의미색은 별도다.

재생성 순서:

```sh
/tmp/ddirori-brand-tools/venv/bin/python docs/brand/ddirori-brand-system/tools/build.py
node docs/brand/ddirori-brand-system/tools/render.mjs
node docs/brand/ddirori-design-system/tools/build.mjs
cd packages/ddirori_web && npm run build
```

플랫폼 아이콘 적용은 `render.mjs --apply`를 명시한다. 폰트·렌더 도구 설치와 환경 변수는 브랜드 운영 README를 참고한다. 기존 `*-blue.svg` 워드마크 파일명은 호환용이며 현재 밝은 화면의 행동색을 사용한다. 이전 원본은 visuals 아래에 보존한다.

## 서비스 연계 계약

웹 `ServiceLink`와 Flutter `DdiroriServiceLink`는 제품·이름·설명·연결 상태·콜백을 받는다. 외부 이동과 설치 안내는 행동 레이블로 구분한다. unavailable 또는 콜백 없음은 실제 동작을 차단한다. URL 검증, 계정·설치 상태 확인과 실제 라우팅은 제품이 소유한다.

비교 화면은 예시임을 표시하며 새로운 서비스 연결을 제공한다고 주장하지 않는다. 실제 데이터 공유·통합 계정·결제를 추가하지 않았다.

## 악보·사보 적용 경계

플레이·스코어는 기존 공통 테마 연결을 통해 대표 화면과 컨트롤에 새 색을 적용하고 iOS/Android 런처를 갱신했다. 제품 식별자·데이터·기능 동선은 유지했다. 스코어 빠른 접근 카드의 고정 높이는 실제 글꼴·글자 확대 기준의 계산으로 교체해 두 줄 제목과 마지막 페이지 행이 겹치지 않게 했다. 위젯 캡처는 테스트 샘플이며 스토어 촬영 산출물이 아니다.

Chromatics의 도구 분류·성부·속성 dock·편집 명령은 제품 전용이다. 기존 CSS의 `--inc-color-*`를 이후 단계에서 공통 의미 역할에 연결하되 악보 지면과 표기 색은 유지한다. 사보 UI 전체를 이번 작업에서 이행했다고 표현하지 않는다. 새 팔레트의 툴바·선택·작업 면은 공통 카탈로그에서 비교한다.

## 검증과 후속 판단

실행 결과는 `evidence/refresh/` 및 현재 artifact-validation에 기록한다. 생성물·대비 계산·컴포넌트 테스트·브라우저 렌더링·앱 위젯 렌더링은 각각의 범위로 해석한다. 물리 기기 런처·VoiceOver·색각 사용자 식별·장시간 연주 피로도·최종 브랜드 선택은 별도 확인 사항이다.

다음 제품 이행은 스코어의 나머지 문서 주변 도구, 플레이의 상세 감상 화면, Chromatics의 도구·패널 순서로 진행한다. 기존 기능 계약을 유지하며 각 앱의 메타데이터와 검증을 함께 갱신한다.


## 이번 실행 결과

공통 Flutter 20개, React 23개, 플레이 컴포넌트·시범 화면 14개, 스코어 시범 화면 7개로 총 64개 테스트를 통과했다. 스코어는 기본 테스트 글꼴과 Pretendard 캡처 조건을 각각 확인했다. Flutter 공통 패키지와 스코어 정적 분석, React 빌드, 두 앱 iOS 메타데이터 check도 통과했다.

네 팔레트의 88개 색상 쌍과 권고안의 의미 토큰 30쌍을 검사했고 브랜드 자산 164개 검사 항목을 통과했다. [실행 요약](evidence/refresh/summary.json), [브라우저 검사](evidence/refresh/browser.json), [팔레트 대비](evidence/refresh/contrasts.json)를 참고한다. 대비 검사는 명시한 색상 쌍의 계산이며 전체 접근성 인증이 아니다.
