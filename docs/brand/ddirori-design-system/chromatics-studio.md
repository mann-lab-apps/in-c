## 상태 문법

입력 파라미터와 선택 객체 속성은 분리한다. 입력 모드의 음가 변경은 선택 음표를
수정하지 않는다. 다중 선택의 서로 다른 값은 `여러 값`으로 표시하고 명시적 선택
때만 해당 객체들을 함께 변경한다. 선택 없음에서 객체 편집은 비활성이다.

선택은 파란 윤곽과 `선택` 글자, 재생 위치는 녹색 수직선과 상태 글자,
입력은 검정 점선, 범위는 보라 연결선·원형 끝점과 시작/끝 이름으로 구분한다.
색뿐 아니라 형태와 텍스트를 유지한다. 현재 재생선은 고정 위치 fixture이지
움직이는 오디오 시계가 아니다. 끝점 위치 변경은 속성 선택으로만 제공한다.

좁은 창에서는 악보, 팔레트, 속성을 세로 배치한다. 제목과 상태는 별도 행을
사용할 수 있고, 긴 제목을 무리하게 옆으로 압축하지 않는다. 패널을 닫으면
포커스가 숨겨진 자식에 남지 않고 해당 패널 토글로 돌아간다.

## Acceptance와 실패 조건

- 입력/선택 값 분리, 혼합값·undo/redo, span 역순 차단을 테스트한다.
- 검색 초기화가 기호를 자동 삽입하거나 선택하지 않는다.
- 도크 폭 경계와 숨김 후 복원을 유지한다.
- 잘못된 숫자와 미확인 위험 행동은 실행하지 않는다.
- 실패 fixture에서 성공 문구가 나타나지 않으며 재시도할 수 있다.
- 테마 2종 × 밀도 2종 × 폭 390/840/1440 × 글자 100/200%를 확인한다.
- 가로 넘침, 컨트롤 텍스트 잘림, 제목의 글자 단위 줄바꿈, 누락 glyph,
  modal 닫기/포커스 복귀 실패는 검증 실패로 처리한다.
- 자동 검사 통과와 별도로 생성 캡처를 열어 확인한다.

## 재현

`packages/ddirori_web`에서 루트 Node 의존성이 준비된 환경을 사용한다.

```sh
npm test
npm run typecheck
npm run build
npm run build:studio
npm run dev:studio
```

사보 경로: <http://127.0.0.1:8062/studio.html>.
일반 카탈로그는 기존 `index.html`을 유지한다. 사보 빌드는 저장소의
`.tmp/ddirori-studio/`에 생성하며 제품 릴리즈 빌드가 아니다.

별도 터미널에서 다음을 실행한다. Playwright가 기본 경로에 없으면 실제
설치 모듈의 절대 경로를 지정한다. 브라우저는 독립 Chromium이다.

```sh
DDIRORI_PLAYWRIGHT_PATH=/absolute/path/to/playwright/index.mjs npm run verify:studio
```

주소는 `DDIRORI_STUDIO_URL`, 증거 경로는 `DDIRORI_STUDIO_EVIDENCE`로 변경한다.
기본 증거 경로는 `/private/tmp/ddirori-studio-evidence`다. report.json과 실제
캡처가 생성되며 수동으로 통과나 이미지 hash를 기입하지 않는다.

## 이행 순서

먼저 카탈로그 디자인을 검토하고 입력 툴바 → 속성 → 도크 순서로 실제 앱에
한 영역씩 연결한다. 기존 명령과 저장 계약을 유지하며, 사용자 선택과 파일을
샘플 상태로 대체하지 않는다. 전체 제품 전환은 이 카탈로그의 완료 조건이 아니다.
제품 이행 때 실제 단축키·IME·undo/redo·저장·내보내기 회귀와 해당 메타데이터를
갱신한다. 오디오·파일 안전성은 이 카탈로그 검사로 인증하지 않는다.
