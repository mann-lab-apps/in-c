# 팔레트와 최신 아이콘 검토

최종 대표색은 미확정. 현재 trial lime를 제품 전반에서 자동으로 바꾸지 않는다. 값은 [palette-candidates.json](../palette-candidates.json)에서 읽어 시안의 scoped CSS 변수로만 적용했다.

## 여섯 후보에서 세 후보로

| 후보 | 이번 판단 | 화면에서 보는 차이 |
| --- | --- | --- |
| 바이올렛 | **우선 추천** | 명확한 진한 행동색과 밝은 대표색을 분리하기 쉽다. 흰 바흐 머리·살구 얼굴·검정 음형과 공존하고, 오류·성공의 빨강/초록과 구분이 쉬움. 창작 도구의 인상을 줄 수 있다는 디자인 해석이며 조사로 입증한 선호가 아님 |
| 파랑 | 유지 | 읽기/재생 UI에 친숙하고 안정적. 기존 아이콘 후보와 이어지지만 비슷한 소프트웨어와의 구별은 형태·이름에 더 의존 |
| 코럴 | 유지 | 같은 흰 작업 면에서도 따뜻한 인상. 바흐 얼굴과 가까워 겹치는 면은 흰 머리·외곽으로 분리. 오류색으로 오해되지 않게 오류는 기호·문구를 필수 병기 |
| 틸 | 이번 비교 제외 | 좋은 대비 확보 가능하나 성공/재생 표시의 초록과 역할 구분 부담. 폐기·사용불가 판단은 아님 |
| 옐로 | 이번 비교 제외 | 대표 면으로 선명하지만 행동에는 어두운 갈색 계열이 필요해 대표색과 명령의 인상 차이가 큼. 누르스름한 전체 화면으로 되돌아갈 위험을 줄임 |
| 라임 | 이번 비교 제외 | 현재 trial 사용을 최종 선호로 간주하지 않음. 어두운 올리브 행동색이 사용자가 지적한 탁한 인상과 이어질 수 있음 |

음악에 본래 대응하는 특정 색이라고 주장하지 않는다. 바이올렛의 의미는 “자기 음악을 시도하는 창작 공간”이라는 브랜드 선택이며, 색 자체의 보편적 사실은 아니다. 카카오/네이버 색을 복제하지 않고 대표색·중립면·역할 심벌의 분리를 참고한다.

| 역할 | 바이올렛 | 파랑 | 코럴 |
| --- | --- | --- | --- |
| 대표 면 + 검정 심벌 | #D0BFFF | #A5D8FF | #FF927E |
| light 행동 + 흰 글자 | #6741D9 | #1971C2 | #9D4034 |
| light 선택 면 | #F3F0FF | #E7F5FF | #FFF0EC |
| dark 행동 + 어두운 글자 | #D0BFFF | #A5D8FF | #FFB4A4 |

나머지 dark/hover/pressed/focus 값은 원 JSON 참조. 대표색을 body 글자·모든 툴바 바탕으로 쓰지 않는다. 배경/지면/성공·주의·오류/주석·성부/현재 재생 의미는 고정한다. 성공 #246145 / 경고 #805500 / 오류 #AF344B(light), dark는 tokens.json 역할값 유지. 현재 재생은 색+재생 glyph+텍스트로 구분하고 palette primary를 도메인 상태 저장값으로 쓰지 않는다.

**비교 근거:** 같은 Score fixture·초기상태의 [light](evidence/proposal-palettes-light.png) / [dark](evidence/proposal-palettes-dark.png), 실제 Flutter의 [violet](evidence/actual-score-violet-light.png) / [blue](evidence/actual-score-blue-light.png) / [coral](evidence/actual-score-coral-light.png), [실제 dark](evidence/actual-score-violet-dark.png). UI는 동일하고 색만 다르다. 앱의 현재 데이터와 리뷰 fixture는 다르므로 실제↔시안 비교는 픽셀 diff가 아니라 구조 검토다.

[contrast.json](evidence/contrast.json)은 본문·보조·행동·선택·대표색 글자·오류·성공·주의4.5:1, 포커스/입력 경계3:1에 대한 불투명 토큰 쌍 검사다. 얇은 구분선은 입력 경계가 아니다. 회색조 아이콘 확인은 색각 시뮬레이션/실제 색각 사용자 검증을 대신하지 않는다. UI 선택 체크·오류 기호·앱 외곽 역할로 색만의 의존을 줄였다.

## v8 아이콘

원본 [icon-family-v8](../../ddirori-brand-system/icon-family-v8/README.md) 그대로. 브랜드 독립 음형 / Play 삼각형 / Studio A 긴 연필 / Score 펼친 악보책. 64·64·점32 음가, 상단 짧은 beam·하단 공통3beam, 끝 기둥·head 접합을 수정하지 않았다. 도요새·기러기·다른 장식은 추가하지 않았다.

[이름 포함](evidence/proposal-icons-named.png), [이름 숨김](evidence/proposal-icons-blind.png), [단색·회색조](evidence/proposal-icons-mono-gray.png). 리뷰 모드에서는 각각 분리 toggle 가능. 밝고 어두운 바탕에16/24/32/48/64px를 나란히 표시. 앱 목록/홈/작업 표시줄을 위한 크기 샘플이며 실제 OS launcher 설치 캡처는 아니다.

관찰: Play의 삼각형은 외곽이 가장 쉽게 구분된다. Studio와 Score는48px 이상에서 연필/책 차이가 더 드러난다. 16–24px의 내부 음형은 얼룩처럼 모일 수 있고 32px도 정확한 beam 수를 읽기 어렵다. 작은 크기에서 음가 판독을 합격 기준으로 삼지 않는다. 앱 목록에서는 이름 필수; 작업 표시줄은 OS tooltip/accessibility label 유지. 이 관찰은 디자인 검토이며 사용자 정답률이 아니다.

## 사람 대상 5분 검증 자료 — 미실시

1. 무레이블48px 후보를 순서를 바꿔 제시한다. “재생 / 악보 읽기 / 악보 만들기 / 모브랜드”와 연결하고, 모름도 허용한다. 첫 반응·확신(1–5)·혼동 이유 기록.
2.24px에서 같은 과제. 이후 이름을 표시해 실제 홈 화면에서 찾도록 한다. 초반에 음형의 의미/정답을 알려주지 않는다.
3. mono/grayscale와 dark에서 다시 찾는다. 시각 조건·viewport·기기 배율 기록.
4. 같은 Score 화면의 세 색을 순서를 바꿔 보여준다. “귀여움”과 “오래 읽기 편함”을 각각 선택하고, 주 행동/오류를 찾아달라고 한다.
5. 바흐가 있는 첫 빈 상태와 없는 검색 없음 상태를 보여주고 다음 행동을 설명하게 한다.

기록: participant 익명ID / 후보순서 / 크기·theme / 답·정답여부 / 시간 / 확신 / 혼동쌍 / 짧은 이유. 결과 없음은 빈칸으로 남긴다. 5–8명의 탐색적 검증부터 시작하고 전체 시장 통계로 일반화하지 않는다. Studio↔Score 혼동이 반복되면 음가를 망가뜨리는 대신 외곽 크기·비율을 별도 revision으로 재검토. 대표색 최종 선택은 사용자 확인 대기.
