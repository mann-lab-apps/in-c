# 세 앱 화면 계약

R1은 기존 [foundations](../foundations.md)·[components](../specifications/README.md)를 대체하지 않는 화면 구성 계층이다.

## 공통 구조와 차이

| 영역 | 공통 | Play | Score | Studio |
| --- | --- | --- | --- | --- |
| 제목 | 화면명 24/700, 보조14/400, 역할 아이콘32 + 앱명 | 내 라이브러리 | 내 악보 / 열린 악보명 | 문서명 + dirty/저장 상태 |
| 탐색 | 제목 아래 검색·필터, 주요 행동 한 개 | 작품·작곡가·파일 범위는 기존 검색 보존 | 검색·정렬·즐겨찾기·상세필터 보존 | 명령 분류·도구 검색, 악보 내부 찾기와 구분 |
| 내용 | 평평한 행·1px 구분선, 명칭16/600, 설명14 | 작품→녹음→악장 | 악보 행 / 흰 PDF 지면 | 흰 기보 지면 + 도구·속성 dock |
| 주요 상태 | 글자·기호·색 함께 | 현재 재생·파일 가용성 | 선택 수·필터·페이지 | 선택 범위·입력 모드·sp |
| 행동 | 기본 높이48, compact32는 정밀 포인터만 | 재생/일시정지 | 가져오기/열기/편집 | 현재 선택에 유효한 명령 |

간격: 공통 토큰 4/8/12/16/24/32. 앱 좌우 gutter 좁음16, 중간24, 넓음32. 헤더→본문24, 검색→필터16, 행 상하16, 아이콘→명칭12. 긴 제목은 2줄 이상 허용하며 행 높이를 고정하지 않는다. 도구 glyph18–20, 행 glyph22–24. 장식용 브랜드 아이콘을 모든 행에 반복하지 않는다.

배경은 light #FFFFFF / dark #181818, 분리 면 #F5F5F5 / #2C2C2C. 작업 지면은 흰색·검정 음표 고정. 카드 radius12는 미리보기·독립 패널에만 사용. 선택은 얇은 강조와 tint·체크로 표현하며 외곽선 중첩 금지. focus는 기존 focus 토큰 별도 사용. 리뷰의 앱 외곽 frame16은 제품 UI 토큰 확장이 아니다.

시안에는 작은 보조 캡션 12–13px를 리뷰 설명에 사용했다. 서비스 구현에서 중요한 설명은 기존 description14를 사용하고, 작은 캡션에 복구 정보를 숨기지 않는다. 리뷰 CSS를 제품 코드에 통째로 복사하지 않고 공통 토큰으로 대응시킨다.

## 반응형·큰 글자

- 모바일 320–599: 한 열, gutter16, touch48. 검색과 필터는 wrap. 행 보조 행동은 이름/선택과 별도 target. 목록 본문과 재생/뷰어 bottom 영역이 가려지지 않게 safe area + footer 높이만큼 inset.
- 600–1023: gutter24. Score 가변 높이 두 열은 실제 설정과 큰 글자 조건 유지. Play 작품/녹음 보조 패널은 공간이 충분할 때만. 정보의 읽기 순서는 한 열과 동일.
- 1024+: gutter32, Studio 지면/속성 나란히. 기존 dock 폭200–360 설정 보존, 신규 기본280. 기보 지면 scroll/pan과 chrome overflow 분리.
- 글자200%: 고정행/말줄임 강제 금지, 툴바 wrap 또는 의미 있는 그룹별 scroll. 선택 수/저장/오류를 밀어내지 않는다. Studio가 좁으면 속성 접기·복원 trigger를 제공하고 focus 복귀; 리뷰는 아래 배치로 공간을 설명한다.
- 리뷰의 세 앱 비교는1180 이하 한 열로 바뀐다. 이것은 리뷰판의 breakpoint이며 앱 window breakpoint가 아니다.
- 다크 모드는 chrome와 텍스트만 전환. PDF 원본·기보 출력·주석/성부 색은 제품 의미 계약 유지. dark Studio는 목표 설계이며 현재 실제 panel light 적용과 구분한다.

## 상태·바흐·문구

기준: [voice](../../ddirori-brand-system/voice.md), [motion](../../ddirori-brand-system/motion.md).

| 상태 | 표시·행동 | 바흐·모션 |
| --- | --- | --- |
| 처음 빈 목록 | “첫 음악을 담아볼까요?” + 무엇을 가져오는지 + 가져오기. Play 데모 자동 주입 금지 | 놀란 바흐64, 빈 상태 영역 1회. 반복 애니메이션 없음 |
| 검색 없음 | 검색어나 필터 수정/초기화 | 캐릭터 없음 |
| 읽기·준비 중 | 작업명 + Progress. 기존 내용을 유지할 수 있으면 전면 제거하지 않음 | 기존 음형 1:1:3; reduced motion 정지. 임의 percent 금지 |
| 저장 중 | 입력 readonly, 재실행/닫기/Back 제어, “분류 저장 중” | 작은 음형과 작업명; 저장이 끝나면 제거 |
| 완료 | 실제 성공 뒤 인라인 확인, 기존 작업 계속 | 일상 저장에는 바흐 없음. 최초 가져오기 완료에 happy48 선택 가능, 세션 중 1회 이하 |
| 파일/저장 오류 | 무엇이 실패했는지 + 보존한 내용 + 연결/재시도. 진단은 펼침 | 캐릭터·자동 소리 없음. 실패 즉시 로딩 중단 |
| 사용 불가 | disabled + 인접한 사유(파일 없음/선택 없음 등) | 모션 없음 |

바흐 빈도는 제품 UI 규칙이며 분석 추적/계정 저장을 새로 요구하지 않는다. 연습·감상·사보 중 상시 캐릭터·자동 효과음 없음. 진행률은 실제 분모가 있을 때만 숫자로 표시한다. 리뷰 전역 상태 selector는 외부 제어 예제이지 앱 상태 머신이 아니다.

## 접근성과 상태 소유

제목→검색→필터→내용→재생/보조 패널 순서. 툴바 group label, icon-only accessible name, checkbox checked, 선택은 색 외 체크·수 표시. 오류 alert는 작업당 한 번, 진행 상태는 polite; 시간 매 프레임 읽기 금지. 입력 중 전역 단축키 차단은 앱이 소유한다. Dialog 닫기 후 원 trigger로 focus, trigger가 사라졌으면 해당 목록 heading으로 복귀. 숨은 dock에는 focus를 남기지 않는다.

실제 데이터와 draft 분리, 저장 요청 중 중복 명령 금지, 실패는 draft·선택·scroll 보존, 성공 후에만 controller 갱신·닫기. 목록 filter 변경은 ID 선택을 암묵 삭제하지 않는다. 화면 변경 때문에 재생 큐·현재 페이지·undo·저장된 필터를 초기화하지 않는다.
