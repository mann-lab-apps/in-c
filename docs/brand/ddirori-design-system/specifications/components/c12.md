# C12 Segmented

설계: 현행 + 명시한 후속 목표. 구현: React 공개 구현, Flutter 공개 구현. 검증: 소스 대조; 과거 테스트 기록과 이번 문서 검증은 별개. 계층 B/C.

## 목적·구조

같은 성격의 소수 선택지 중 하나. 콘텐츠 패널은 Tabs.

surfaceMuted group padding4/gap4 → tool radius8 options. selected 면·radio 의미. Flutter SegmentedButton 합성.

외형 프로파일: [choice](../component-rules.md). 토큰 값·단위는 [F-REF](../token-reference.md). 별도 size prop이 없는 항목은 조상 density로 결정한다.

## 상태·전이·접근성

웹 roving tabindex, 방향키 순환/Home/End로 focus+값 함께 이동; disabled 건너뜀. Flutter selected Set·allowEmpty=false·icons/showSelectedIcon, native 동작 유지.

웹 scalar와 Flutter Set 차이. Flutter 선택은 유효한 한 값(allowEmpty면0개)이어야 한다. external invalid/빈 options의 제품 fallback은 host.

공통 입력·상태 행렬의 적용 여부는 [C-BASE](../component-rules.md)를 따른다. 지원 API 밖의 success/error/readOnly 등을 새 prop처럼 사용하지 않는다. 정적 표시의 입력·busy 상태는 N/A, 동적 자식은 각 자식 계약 적용. 긴 한국어·영문은 가변 높이를 쓰며 진단·파일 경로를 기본 접근성 이름에 넣지 않는다.

## 실제 API·기본값

React: [SegmentedControl](../api-react.md#SegmentedControl)
Flutter: [DdiroriSegments](../api-flutter.md#DdiroriSegments)

위 API 부록은 소스 서명·필수 인자·기본값·callback 타입을 제공한다. 값/키는 host가 소유하며 비동기 지원 여부는 각 서명을 따른다. 부록과 실제 export가 달라지면 재추출 후 계약 변경을 검토한다.

## 최소 사용·서비스 연결

React (`UI`는 `@ddirori/ui`; 아래 콜백은 배선 자리이며 앱 상태 저장을 구현하지 않는다):

```tsx
<UI.SegmentedControl label="보기" options={[{value:"list",label:"목록"}]} value="list" onChange={() => {}} />
```

Flutter (`material.dart`와 `ddirori_ui.dart`, context는 해당 화면 BuildContext):

```dart
DdiroriSegments<String>(options: const {'list': '목록'}, selected: const {'list'}, onChanged: (_) {})
```

좋은 사용: 서비스 adapter가 표시값/가용 동작을 계산해 이 API로 전달한다. 나쁜 사용: 공통 위젯이 앱 repository/엔진을 import하거나 예제의 no-op 콜백을 실제 저장 성공으로 취급한다. [서비스 명세](../README.md)의 해당 화면 조합에 연결한다.

## 수용 조건·근거
