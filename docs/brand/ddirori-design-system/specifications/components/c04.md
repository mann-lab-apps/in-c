# C04 Field / Input / Textarea / Search

설계: 현행 + 명시한 후속 목표. 구현: React 공개 구현, Flutter 공개 구현. 검증: 소스 대조; 과거 테스트 기록과 이번 문서 검증은 별개. 계층 B/C.

## 목적·구조

label·도움말·오류를 갖는 입력. Search는 query 표시/지우기이며 검색 실행 엔진은 host.

Field render props id/description/invalid/required → 입력. Input 한 줄, Textarea rows 기본3/세로 resize. Flutter maxLines 기본1, 여러 줄로 Textarea 합성.

외형 프로파일: [field](../component-rules.md). 토큰 값·단위는 [F-REF](../token-reference.md). 별도 size prop이 없는 항목은 조상 density로 결정한다.

## 상태·전이·접근성

Input/textarea는 native 입력 props, Search는 controlled string. 오류가 help보다 우선. clear는 빈 문자열 요청, disabled/readOnly에서 차단. Flutter controller는 내부 State 생성·dispose, 외부 value 변경 시 커서 위치 범위를 보정한다.

React Input id는 내부 생성값으로 대체됨. React Field required 표시/ARIA, Input native required, Flutter required는 label 표기일 뿐 자동 validation 없음. ref/controller 공개 주입 없음. IME 조합 중 host가 문자를 가공하지 않는다.

공통 입력·상태 행렬의 적용 여부는 [C-BASE](../component-rules.md)를 따른다. 지원 API 밖의 success/error/readOnly 등을 새 prop처럼 사용하지 않는다. 정적 표시의 입력·busy 상태는 N/A, 동적 자식은 각 자식 계약 적용. 긴 한국어·영문은 가변 높이를 쓰며 진단·파일 경로를 기본 접근성 이름에 넣지 않는다.

## 실제 API·기본값

React: [Field](../api-react.md#Field) · [Input](../api-react.md#Input) · [Textarea](../api-react.md#Textarea) · [Search](../api-react.md#Search)
Flutter: [DdiroriInput](../api-flutter.md#DdiroriInput) · [DdiroriSearch](../api-flutter.md#DdiroriSearch)

위 API 부록은 소스 서명·필수 인자·기본값·callback 타입을 제공한다. 값/키는 host가 소유하며 비동기 지원 여부는 각 서명을 따른다. 부록과 실제 export가 달라지면 재추출 후 계약 변경을 검토한다.

## 최소 사용·서비스 연결

React (`UI`는 `@ddirori/ui`; 아래 콜백은 배선 자리이며 앱 상태 저장을 구현하지 않는다):

```tsx
<UI.Input label="제목" value="연습" onChange={() => {}} required />
```

Flutter (`material.dart`와 `ddirori_ui.dart`, context는 해당 화면 BuildContext):

```dart
DdiroriInput(label: '제목', value: '연습', onChanged: (_) {}, required: true)
```

좋은 사용: 서비스 adapter가 표시값/가용 동작을 계산해 이 API로 전달한다. 나쁜 사용: 공통 위젯이 앱 repository/엔진을 import하거나 예제의 no-op 콜백을 실제 저장 성공으로 취급한다. [서비스 명세](../README.md)의 해당 화면 조합에 연결한다.

## 수용 조건·근거

Given 외부 query 변경, When rerender, Then 화면 값 동기화. Given error+help, Then 오류 설명 연결. readOnly의 지우기는 실행 불가.

시각 검사: light/dark, 임시 강조색 교체, narrow/200% 긴 label, compact 포인터·touch 최소 영역. 수동 검사: 실제 플랫폼 입력·스크린리더. 후속 작업은 [검증](../verification.md)과 [작업 패키지](../work-packages.md)를 따른다.

## 실제 적용 후속 · 2026-10-24

Flutter DdiroriInput은 active composing·readOnly·disabled 상태의 onSubmitted를 차단한다. required는 계속 host 검증 책임이다. 플랫폼 실제 IME는 실기기 수동 범위다.
