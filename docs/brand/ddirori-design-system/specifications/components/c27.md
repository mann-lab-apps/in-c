# C27 Dialog / Confirm / Sheet

설계: 현행 + 명시한 후속 목표. 구현: React 공개 구현, Flutter 공개 구현. 검증: 소스 대조; 과거 테스트 기록과 이번 문서 검증은 별개. 계층 B/C.

## 목적·구조

주의 전환·폼·확인. 보조 설명은 non-modal Popover.

title+close→body→actions. dialog width560/viewport-32/padding24, sheet width720/max85dvh/상단 radius16. Flutter route 구조·padding20/24 예외.

외형 프로파일: [overlay](../component-rules.md). 토큰 값·단위는 [F-REF](../token-reference.md). 별도 size prop이 없는 항목은 조상 density로 결정한다.

## 상태·전이·접근성

웹 controlled open, native showModal/Tab 순환/Escape onClose/focus 복귀. Confirm은 host busy 또는 내부 Promise pending 동안 닫기·취소·중복 실행을 차단한다. 실패는 host error 또는 안전한 기본 문구로 표시하고 재시도를 허용한다. 닫았다 다시 연 세션은 이전 완료·실패에 덮이지 않는다. Flutter showDialog<T?>/sheet<T?> 결과, confirm bool 반환 후 host가 작업.

성공 후 open=false 전환은 여전히 host 책임이다. Dialog는 busy=false 기본값을 가지며 true일 때 닫기/Escape를 차단한다. Flutter 실제 Score bulk sheet는 앱 내부 stateful adapter로 busy/입력 보존/실패/재시도를 처리한다. Flutter helper에는 busy/error 인자 없음. 웹 backdrop click 자동 닫기 없음. 별도 side drawer는 미구현.

공통 입력·상태 행렬의 적용 여부는 [C-BASE](../component-rules.md)를 따른다. 지원 API 밖의 success/error/readOnly 등을 새 prop처럼 사용하지 않는다. 정적 표시의 입력·busy 상태는 N/A, 동적 자식은 각 자식 계약 적용. 긴 한국어·영문은 가변 높이를 쓰며 진단·파일 경로를 기본 접근성 이름에 넣지 않는다.

## 실제 API·기본값

React: [Dialog](../api-react.md#Dialog) · [ConfirmDialog](../api-react.md#ConfirmDialog)
Flutter: [showDdiroriDialog](../api-flutter.md#showDdiroriDialog) · [showDdiroriConfirmDialog](../api-flutter.md#showDdiroriConfirmDialog) · [showDdiroriSheet](../api-flutter.md#showDdiroriSheet)

위 API 부록은 소스 서명·필수 인자·기본값·callback 타입을 제공한다. 값/키는 host가 소유하며 비동기 지원 여부는 각 서명을 따른다. 부록과 실제 export가 달라지면 재추출 후 계약 변경을 검토한다.

## 최소 사용·서비스 연결

React (`UI`는 `@ddirori/ui`; 아래 콜백은 배선 자리이며 앱 상태 저장을 구현하지 않는다):

```tsx
<UI.ConfirmDialog open={false} title="삭제" onClose={() => {}} onConfirm={() => {}}>선택 자료를 삭제할까요?</UI.ConfirmDialog>
```

Flutter (`material.dart`와 `ddirori_ui.dart`, context는 해당 화면 BuildContext):

```dart
showDdiroriConfirmDialog(context: context, title: '삭제', message: '선택 자료를 삭제할까요?', confirmLabel: '삭제', danger: true)
```

좋은 사용: 서비스 adapter가 표시값/가용 동작을 계산해 이 API로 전달한다. 나쁜 사용: 공통 위젯이 앱 repository/엔진을 import하거나 예제의 no-op 콜백을 실제 저장 성공으로 취급한다. [서비스 명세](../README.md)의 해당 화면 조합에 연결한다.

## 수용 조건·근거

Given 실패 저장, Then 값/모달 유지와 error를 host가 제공. Escape 취소는 부작용 없이 복귀. busy 닫기 요구는 외부 busy와 함께 검증.

시각 검사: light/dark, 임시 강조색 교체, narrow/200% 긴 label, compact 포인터·touch 최소 영역. 수동 검사: 실제 플랫폼 입력·스크린리더. 후속 작업은 [검증](../verification.md)과 [작업 패키지](../work-packages.md)를 따른다.
