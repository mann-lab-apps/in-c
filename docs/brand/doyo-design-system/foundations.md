# 기초 규칙

## 브랜드에서 UI로

기준은 [선택한 A 팔레트](../doyo-visuals/PALETTE.md)와 v4의 앞으로 편 머리·부리, 올라간 배선, 뒤통수로 이어지는 등선이다. 코코아는 새·워드마크·기본 글자, 블루그레이는 대표 아이콘 바탕과 브랜드 면적, 짙은 청색은 행동을 맡는다. 음악 기능마다 새의 신체 부위를 대응시키는 규칙은 이번 시스템에 넣지 않았다.

Figma에서는 작은 크기에서도 작동하는 형태와 제품군의 공통 문법을 참고한다. 고유 로고·색·아이콘을 복사하지 않는다. [Figma 공식 제품 아이콘 제작기](https://www.figma.com/blog/the-making-of-a-product-icon/)

새는 브랜드·빈 화면·로딩에서 쓴다. 파일 저장·재생·주석 같은 명령의 기능 아이콘을 모두 새로 바꾸지는 않는다. 현재 로딩 벡터는 승인한 래스터 실루엣을 참고해 직접 만든 컴포넌트용 좌표이며 최종 상표용 벡터 마스터와 구분한다.

## 색의 계층

| 계층 | 예 | 변경 방법 |
| --- | --- | --- |
| 브랜드 | ink, bluegray, paper, sand | 선택한 원색을 유지 |
| 의미 | text, surface, action, focus, error | 밝은/다크 역할에 맞춰 결정 |
| 악보 | paper, notation, selection, input, playback | 앱 테마와 분리 |
| 컴포넌트 | 버튼의 onAction, 입력의 controlBorder | 의미 토큰을 참조 |

`border`는 카드 구획용이다. 입력칸처럼 조작 영역을 식별해야 하는 경계에는 대비를 확보한 `controlBorder`를 쓴다. 밝은 블루그레이 위에는 코코아를, 짙은 행동색 위에는 흰색을 쓴다. 본문은 4.5:1, 필요한 비문자 UI 단서는 3:1을 기준으로 지정한 색상 쌍을 계산한다. [본문 대비](https://www.w3.org/WAI/WCAG22/Understanding/contrast-minimum.html), [비문자 대비](https://www.w3.org/WAI/WCAG22/Understanding/non-text-contrast.html)

오류·성공·주의는 브랜드의 추가 대표색이 아니라 의미 상태다. 색과 함께 ×/✓/!·문구를 표시한다. 선택은 채움+윤곽+선택 속성으로 표현한다. 접근성 전체 인증이나 색각 사용자 테스트를 완료했다는 의미는 아니다. [색만으로 전달하지 않기](https://www.w3.org/WAI/WCAG22/Understanding/use-of-color.html)

## 타입

| 역할 | 기본 크기 | 굵기 / 행간 |
| --- | --- | --- |
| 본문 | 16 | 400 / 1.55 |
| 조작 라벨 | 14–16 | 600 / 1.55 |
| 부가정보 | 13 | 400 / 1.55 |
| 화면 제목 | 28 | 700 / 1.25 |
| 브랜드 소개 | 40 | 700 / 1.25 |

웹은 동봉한 Pretendard Variable과 시스템 대체 글꼴을 쓴다. Flutter 어댑터는 글꼴을 자동 설치하지 않는다. 제품이 OFL 글꼴을 번들할 때 pubspec과 라이선스를 함께 등록하고 `fontFamily`를 전달한다. 악보 기호는 UI 글꼴과 분리해 기존 음악 렌더러·음악 글꼴을 유지한다.

폰트 크기 확대를 막지 않는다. 긴 한글 제목은 줄바꿈하며, 다국어·큰 글자에서 조작 영역 높이를 자동 증가시킨다. 숫자 BPM·페이지·시간은 같은 폭 숫자를 우선한다. 워드마크용 굵고 촘촘한 글자 설정을 본문 전체에 사용하지 않는다.

## 간격과 형태

간격은 4/8/12/16/20/24/32/40/48/64를 쓴다. 조작부 radius 8, 카드 16, 대화상자 24가 기본이다. pill은 짧은 상태·필터에만 사용한다. 카드와 모든 툴바를 극단적인 둥근 모서리로 만들지 않는다. 기본 패널은 얇은 구획선과 면으로 구분하고 그림자를 필수로 하지 않는다.

| 밀도 | 기본 조작 높이 | 주 대상 |
| --- | --- | --- |
| comfortable | 최소 48 | 휴대폰·태블릿·연습 |
| compact | 최소 32 | 마우스 중심 사보 툴바 |
| coarse pointer | 최소 48 | 작은 창 여부와 별개로 터치 입력 |

48은 이 시스템이 선택한 여유 있는 터치 기준이다. WCAG 2.2 AA의 최소 24 CSS px 및 예외 규정을 48로 잘못 인용하지 않는다. CSS px·Flutter logical px·플랫폼 pt는 물리 픽셀과 구별한다. [W3C 대상 크기 최소 기준](https://www.w3.org/WAI/WCAG22/Understanding/target-size-minimum.html)

600 미만에서는 한 열과 래핑을 우선한다. 960 이상에서 작업 성격에 따라 탐색·캔버스·속성을 나눈다. 실제 제품은 창 크기, 입력 장치와 텍스트 배율을 함께 고려한다.

## 모션과 소리

조작 피드백 120ms, 패널 180ms를 기본으로 한다. 로딩 새는 900ms 주기로 내려앉기와 펴기를 반복한다. 몸과 앞다리는 앞으로/아래로 이동하고, 뒷다리는 발을 고정한 채 압축한다. 좌표·진폭은 `tokens.json`과 로딩 geometry에서 생성한다.

움직임 줄이기에서는 정지 도요와 상태 문구를 유지한다. 로딩 동작은 메트로놈 박자·오디오 재생·음정 피드백을 대신하지 않는다. 브랜드 시작음이나 로딩 소리를 자동 재생하지 않는다. 연습·공연 화면에는 장식적인 반복 움직임을 놓지 않고 실제 대기 작업에 필요한 도요만 표시한다.
