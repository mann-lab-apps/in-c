# 검증 결과와 남은 질문

기준일: 2026-10-21. 검증 대상은 독립적인 디자인 문서·토큰·벡터·목업이다. 실제 Flutter/Electron 앱과 실기기 기능·스토어 캡처를 검수한 결과가 아니다.

## 재현 가능한 확인

[실행 기록 JSON](evidence/validation.json)은 `tools/verify.mjs`가 실제 브라우저 동작과 측정 결과로 생성한다. 성공한 각 항목, 원래 대비 값, 브라우저 버전, PNG 목록과 심벌 경계를 포함한다. 시각 검토 판단은 아래에 따로 기록한다.

| 범주 | 확인 내용 |
| --- | --- |
| 토큰 | Light/Dark × Comfortable/Compact의 별칭 존재·순환 여부 |
| 대비 | 각 모드 본문·보조문구·행동·입력 경계·포커스·선택·오류·재생 등 16쌍 |
| 화면 | 브랜드, 모바일 악보함, 모바일/태블릿 열람, 주석/연습, 사보 기본/선택/동시 상태/좁은 창, 컴포넌트의 Light/Dark |
| 경계 | 지정 viewport에서 문서 전체 가로 넘침, 주요 모바일 터치 대상 ≥44px |
| 상호작용 | 검색·빈 결과·즐겨찾기 필터·제목 정렬·악보 열기·페이지 번호·BPM 입력 |
| 키보드 | 대화상자 Tab·Escape·복귀, Enter로 마디 선택, Escape 해제, 패널 접기, 페이지 이동 후 focus 유지 |
| 모션 | reduced motion에서 컨트롤 transition 비활성 |
| 비행 그래픽 | 소개 화면의 1회 모션·요청 시 재생, 모바일 경계, reduced motion에서 정지·재생 버튼 숨김 |
| 자산 | 256 마스터의 16px 가장자리 여백, 윤곽 샘플의 원형 마스크 8px 여백, 원본 SVG에서 PNG 렌더링 |

정상 텍스트는 4.5:1, 의미 있는 컨트롤/상태 경계는 3:1을 기준으로 측정했다. 근거는 W3C의 [텍스트 대비](https://www.w3.org/WAI/WCAG22/Understanding/contrast-minimum.html), [비텍스트 대비](https://www.w3.org/WAI/WCAG22/Understanding/non-text-contrast.html)다. 단색 쌍의 계산이 이미지·투명 합성·모든 화면·접근성 전체의 통과를 뜻하지 않는다.

## 대표 대비

수치는 표시용 반올림이며 합격 판정에는 반올림 전 값을 사용한다.

| 전경 / 배경 | 대비 | 사용 판단 |
| --- | --- | --- |
| Ink / Cream | 11.03:1 | 본문·로고 주변 텍스트 |
| Muted / Cream | 5.20:1 | 보조문구 |
| Ink / Apricot | 6.76:1 | Apricot 버튼의 글자 |
| White / Apricot | 1.75:1 | 일반 본문 조합 금지 |
| Cream / Night | 14.55:1 | Dark 본문 |
| Cream / Night Surface | 11.53:1 | Dark 패널 본문 |

Apricot/Ink는 브랜드 팔레트 계산이며 현재 light 주요 버튼은 Ink/Cream, dark 주요 버튼은 Apricot/Ink다. 측정한 나머지 쌍은 JSON의 색값과 조건을 따른다.

## 렌더링을 보고 수정한 부분

첫 Stage 실루엣은 양 날개가 겹쳐 종처럼 보였다. 대칭 축 사이를 벌려 두 날개가 각각 보이도록 수정하고, 원형 마스크 여백에 맞춰 전체 크기를 82%로 조정했다. 모바일 보기/주석 버튼은 폭이 약 42.75px여서 최소 폭 48px로 보정했다. 사보 선택 영역은 첫 마디와 어긋나고 세로로 과도하게 넓어 예제의 마디 위치에 맞췄다. 선택·입력·재생 동시 상태에서는 입력 라벨의 줄바꿈과 커서 길이도 보정했다.

대표 PNG를 직접 열어 한국어 긴 제목, Dark의 흰 악보, 주석 패널과 악보의 분리, 32/48/64px의 단색 구분을 검토했다. 이는 한 설계자의 시각 검토다. 이름 없이 기능을 맞히는 비율·기러기 인지율·색각 차이가 있는 사용자의 관찰 결과는 아직 없다.

## 재현 명령

루트에서 정적 서버를 실행한다.

```sh
python3 -m http.server 8043 --bind 127.0.0.1
```

다른 터미널에서 벡터/토큰을 재생성하고 검증한다. Node.js와 Playwright, 실행 가능한 Chromium이 필요하다. Playwright는 저장소 밖 별도 경로에 설치할 수 있다.

```sh
python3 docs/brand/gireogi-design-system/tools/build.py

# 실제 설치 경로를 지정한다. 환경 변수 없이 실행하면 일반 모듈 경로와
# Playwright의 기본 브라우저 경로를 사용한다.
GIREOGI_PLAYWRIGHT_PATH=/absolute/path/to/playwright/index.mjs \
GIREOGI_BROWSER_PATH=/absolute/path/to/chromium \
node docs/brand/gireogi-design-system/tools/verify.mjs
```

검토용 원본 악보를 바꾸려면 root에 설치된 VexFlow로 `tools/render-score.mjs`를 실행하고, 별도 Python 환경의 fonttools/brotli로 `tools/outline-score.py`를 실행한다. 중간 파일은 `/tmp/gireogi-practice-score-text.svg`다. 생성 SVG는 음악 기호와 숫자를 경로로 바꿔 외부 음악 폰트 없이 표시된다. 이후 목업 검증을 다시 실행해 PNG를 갱신한다.

라이선스·출처와 사용한 외부 도구는 [자산 출처](assets/PROVENANCE.md)에 정리한다. 제품의 npm/Flutter 의존성이나 lockfile은 수정하지 않았다.

## 남은 사용자 검증

1. **한 가족으로 보이는가.** 이름을 가리고 다섯 아이콘을 보여주었을 때 같은 제품군으로 묶이는가. Note/Studio가 혼동되는가.
2. **기러기의 인상이 적절한가.** 장난감·교육 앱으로 보이는가, 친근한 음악 도구로 보이는가. Play의 잎·Talk의 오리 연상이 문제인가.
3. **두 앱의 밀도가 맞는가.** 연주자가 악보를 여는 속도와 주석/페이지 이동 실수, 작곡자가 입력 모드를 알아차리는 시간을 관찰한다.
4. **브랜드 노출량이 적당한가.** 공연·집중 작업 중 헤더와 색이 방해되는가. 빈 화면의 캐릭터가 충분한 친근함을 주는가.
5. **실제 환경에서도 읽히는가.** 큰 글자·TalkBack/VoiceOver·키보드만 사용·색각 차이·어두운 합주실·태블릿 방향 전환으로 확인한다.

우선 추천은 A 아이콘과 공통 청록/크림, 앱별 제한된 파스텔, 전문 화면의 낮은 장식 강도다. 가장 먼저 확인할 판단은 ‘더 귀엽게’보다 **작은 크기의 Note/Studio 구분과 두 앱의 조작 밀도**다.

## 확정 전 확인 목록

모브랜드·영문 표기·실제 하위 이름을 결정한 뒤 상표 유사성·해당 지정 상품/서비스·동명 소프트웨어·도메인·핸들을 최신 상태로 다시 확인한다. 이 설계 작업은 상표·도메인의 사용 가능성을 새로 판정하지 않았다. 글꼴 설치·수정·재배포 조건과 플랫폼 아이콘 최신 요건도 출시 시점에 확인한다.

현재 남은 범위는 사용자 관찰, 상표와 출시 자산 결정, 제품 적용 및 실제 기능 QA다. 문서와 목업만으로 제품 리디자인이 적용되었다고 표시하지 않는다.
