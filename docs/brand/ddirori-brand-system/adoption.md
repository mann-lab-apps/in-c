# 띠로리 브랜드 제품 적용

## 두 앱의 로컬 시범 적용

| 제품 | 연결 지점 | 적용 내용 | 유지한 제품 책임 |
| --- | --- | --- | --- |
| 플레이 | MaterialApp, 홈, 빈 라이브러리 | 파랑 공통 테마 유지, 제품 심벌·이름·소개, 벡터 바흐, 런처 아이콘 | 작품·녹음·악장·큐·파일·오디오·기기 내 데이터 |
| 스코어 | InCSheetApp, 악보함 검색·목록·상태 | 이름, 공통 밝은/어두운 테마, 제품 서명, Search·Banner·StatePanel·Progress, 런처 아이콘 | SheetLibraryController, 가져오기·저장·검색·필터·즐겨찾기·PDF·주석·입력·연습 엔진 |

스코어는 기존 Clef & Staff다. 정보·피드백 화면에 이전 이름을 병기한다. iOS/Android 표시명과 로컬 메타데이터를 같은 이름으로 맞췄으며 bundle ID·MethodChannel·저장 키·백업 포맷·기존 지원 URL을 유지했다. 버전과 빌드 번호는 올리지 않았다. Android의 기본·원형 런처 참조는 같은 새 adaptive 아이콘으로 연결한다.

스코어 라이브러리에는 다음 표시 수정을 함께 적용했다.

- 리스트 안의 악보 카드에서 높이가 무한한 상황에 Spacer가 들어가 렌더링이 실패하는 문제를 고정 간격으로 수정했다.
- 넓은 화면의 카드 높이와 빠른 접근 카드 높이는 글자 배율을 반영한다.
- 헤더·필터·빠른 접근이 큰 글씨에서 본문을 밀어내지 않도록 악보함에 함께 스크롤되는 헤더를 적용했다.
- 악보함의 하드코딩된 흰 표면을 공통 surface로 바꿨다. PDF 지면과 공연용 흰색 조작은 이 변경으로 대체하지 않았다.

두 앱의 fontFamily 선택 인자는 로컬 캡처와 명시적으로 서체를 제공하는 host를 위한 것이다. 실제 앱은 기본값으로 플랫폼 글꼴을 사용한다. 웹 검토 화면과 윤곽선 워드마크는 동봉 Pretendard를 사용한다.

## 공통 API

Flutter는 `DdiroriProductGlyph`, `DdiroriProductSignature`, `DdiroriBachVector`와 세 표정 enum을 제공한다. 기존 `DdiroriBach` API는 유지하면서 벡터 구현으로 연결했다. 제품 엔진 의존성은 추가하지 않았다. SVG와 네이티브 가족 도형은 같은 좌표 원본에서 생성한다.

React는 `ProductGlyph`, `ProductSignature`, 세 표정의 `Bach`를 제공한다. Flutter·React·생성 SVG의 로딩은 첫 음 120ms·둘째 120ms·셋째 360ms·쉼 600ms 순서를 사용한다. 기존 tokens.json의 1200ms 주기는 유지했다.

## 나머지 제품 이행

| 제품 | 준비된 것 | 실제 제품 변경 전 확인 |
| --- | --- | --- |
| 스튜디오 | 이름·영문명·편집 도구 아이콘 | 데스크톱 타이틀, 파일 연결, 도움말의 Chromatics 병기, 도구 영역·단축키 회귀 |
| 톡 | 이름·영문명·말풍선 아이콘 | 실제 피드·작성 기능 범위와 권리·운영 상태 안내 |
| 스테이지 | 이름·영문명·무대 아이콘 | 공연 정보·홍보 후보·실제 운영과 예매/결제 미지원 구분 |
| 클릭 | 이름·영문명·메트로놈 아이콘 | 박자·템포·오디오와 출시 문구, 해당 iOS 메타데이터 |
| 차임 | 이름·영문명·소리굽쇠 아이콘 | 기준음·드론·튜너의 실제 제공 범위, 해당 iOS 메타데이터 |

외부 스토어, 홈페이지 공개 화면과 원격 지원 URL을 일괄 변경하지 않았다. 공개 채널 전환 시 각 접점의 이전 이름 검색과 지원 동선을 함께 확인한다. 실제 상표·도메인 검토가 완료된 것으로 이름을 안내하지 않는다.

## 기록과 복귀

기존 `ddirori-visuals/round-*`는 탐색·승인 이력을 보존한다. 현재 제작 자산은 이 폴더에서 사용한다. 앱은 기존 컨트롤러와 데이터 경계를 유지하므로 표시 adapter 단위로 수정할 수 있다. 브랜드 자산을 다시 생성할 때 사용자의 다른 소스 변경을 되돌리거나 전체 앱 폴더를 재생성하지 않는다.
