# 띠로리 브랜드 메시지와 문체

## 브랜드 정의

띠로리는 음악을 듣고 연주하고 만드는 사람의 다음 시도를 돕는 음악 도구와 공간이다.

짧은 소개: **음악, 다음 시도로.** 듣고, 연주하고, 만드는 사람들의 음악 도구.

긴 소개: 음악은 한 번의 완성으로 끝나지 않습니다. 다시 들어보고, 한 구절을 연습하고, 새로운 소리를 만들어봅니다. 띠로리는 그 시도를 이어가는 도구를 만듭니다. 각자의 음악이 발견과 응답을 만나 다음 시도로 이어지는 공간을 지향합니다.

공유·발견·응답의 순환은 제품군의 지향점이다. 현재 로컬 앱의 소개에서는 실제 지원하는 파일 가져오기·정리·재생·필기·연습을 말한다. 계정, 클라우드 저장, 공동 편집, 수익 배분 서비스를 이미 제공한다고 쓰지 않는다.

## 약속과 제품 경험

| 메시지 | 근거가 되는 경험 | 설명의 한계 |
| --- | --- | --- |
| 다음 시도를 쉽게 | 악보 검색·세트리스트·연습 도구 | 실력 향상이나 공연 성공을 보장하지 않음 |
| 내가 가진 음악에서 발견 | 플레이의 작품·녹음·악장 구조와 기기 내 추천 | 모든 음악을 제공하는 스트리밍 서비스가 아님 |
| 내 작업을 명확하게 | 저장·삭제·가져오기 결과와 복구 안내 | 확인 전 성공을 표시하지 않음 |
| 음악적 반응을 나누는 공간 | 공연·커뮤니티 제품의 방향 | 실제 구현·운영 중인 기능과 예정 기능을 구분 |

## 문체

환영과 탐색에서는 ‘해볼까요?’, ‘찾아보세요’처럼 가볍게 권한다. 작업 결과는 ‘추가했습니다’, ‘저장하지 못했습니다’처럼 상태를 분명히 말한다. 오류·삭제·권한 안내는 정확성을 우선하고 유머를 넣지 않는다.

캐릭터가 등장해도 모든 안내를 캐릭터의 대사로 만들지 않는다. 바흐의 짧은 반응은 환영·발견·축하에 사용하고, 오류의 원인·수치·시스템 결과는 앱이 설명한다. 전문 용어는 필요한 화면에서 쓰되 실제 행동을 한국어로 풀어준다.

## 상태별 문구

| 상황 | 문구 | 행동과 조건 |
| --- | --- | --- |
| 환영 | 첫 악보를 펼쳐볼까요? | 스코어의 악보 없는 상태, ‘악보 추가’ 제공 |
| 플레이 처음 사용 | 로컬 음원부터 가져오세요. | ‘파일 가져오기’ 또는 지원 환경의 ‘폴더 추가’ 안내 |
| 검색 결과 없음 | 조건에 맞는 악보가 없습니다. | ‘검색/필터 초기화’로 실제 조건을 초기화 |
| 진행률 미상 | 악보함을 불러오는 중 | 정확한 백분율을 만들지 않음 |
| 진행률 있음 | 악보를 가져오는 중 · 60% | 엔진이 제공하는 진행률만 사용; 카탈로그 수치는 데모 |
| 완료 | 악보를 추가했습니다. | 실제 가져오기 완료 후 파일 수를 덧붙일 수 있음 |
| 파일 가져오기 오류 | 악보를 가져오지 못했습니다. 파일을 기기에 내려받았는지 확인해 주세요. | 실제 원인에 맞게 PDF 형식·내려받기 등 확인 방법 제시 |
| 저장 오류 | 변경 사항을 저장하지 못했습니다. | 저장 안 된 범위와 실제 가능한 재시도 행동 표시 |
| 영구 삭제 | 이 감상 기록을 삭제할까요? 삭제한 기록은 되돌릴 수 없습니다. | 원본 음원 삭제와 구분하고 실제 구현에 맞게 결과 설명 |
| 복구 | 백업에서 악보와 세트리스트를 복원합니다. | 덮어쓰기·추가·원본 보존 규칙을 실제 동작에 맞춰 보충 |
| 마이크 권한 | 튜너에서 음정을 확인하려면 마이크 접근을 허용해 주세요. | 사용자가 튜너를 켤 때만 요청 |

‘앗! 실패했어요’, ‘바흐도 당황했어요’처럼 오류를 장난스럽게 묘사하지 않는다. 저장이 실패했는데 ‘괜찮아요’라고 안심시키거나 자동 복구를 약속하지 않는다. 버튼에는 ‘확인’보다 ‘다시 가져오기’, ‘기록 삭제’처럼 실제 행동을 쓴다.
