## 후속 사용자 피드백: Excalidraw를 색상·그래픽 레퍼런스로 검토

2026-10-23: 사용자는 현재 카탈로그가 상투적이며 누르스름한 인상이 강하고, 당근에서 기대한 간결함을 구현하지 못했다고 평가했다. 라임·올리브 적용은 완료된 로컬 실험이며 승인된 시각 방향으로 취급하지 않는다. 이후 사용자는 Excalidraw의 빗금·이중선에 영감을 받았고 색상 구성도 참고하고 싶다고 밝혔다.

Excalidraw 공식 소스는 기본 캔버스와 입력·도구 패널에 흰색을 사용하고, UI 강조색 및 선택 상태의 색을 별도로 정의한다. 도형 팔레트는 짙은 선과 옅은 채움의 단계를 구분한다. UI 강조색과 사용자가 그리는 콘텐츠의 색을 하나의 역할로 합치지 않는 점을 참고한다. [기본 캔버스](https://github.com/excalidraw/excalidraw/blob/master/packages/excalidraw/appState.ts), [UI 테마](https://github.com/excalidraw/excalidraw/blob/master/packages/excalidraw/css/theme.scss), [도형 팔레트](https://github.com/excalidraw/excalidraw/blob/master/packages/common/src/colors.ts).

띠로리의 다음 검토에서는 흰색·무채색을 기반으로 UI 강조색을 제한하고, 컬러와 손그림 질감을 바흐·소개 그래픽·콘텐츠 표현에 배치한다. 빗금과 이중선은 실제 작은 크기와 정보 밀도에서 비교한다. 기보·음형의 정확한 구조와 작은 도구의 식별성을 보존한다. 구체적인 대표색·질감의 적용 범위는 미확정이다.

레퍼런스 역할은 서비스 연계에 카카오·네이버, 생활 서비스의 간결함에 당근, 색상 구성과 손그림 표현에 Excalidraw로 갱신한다. Wise·Monzo·Mailchimp와 아래의 라임 권고는 이전 비교 기록으로 남긴다. 다음 시안은 실제 악보함 한 화면에서 먼저 평가하고 공통 시스템으로 확장한다.

> 현재 기준: [중립 바탕·여섯 강조색·콘텐츠 12색](../ddirori-design-system/color-system.md). 이전 라임·올리브 배경 시안은 승인된 방향이 아니다. 라임은 임시 강조색으로만 유지하며 대표색은 검토 중이다.

### Wise를 먼저 추천하는 이유

사용자가 말한 ‘음악적으로 모험하는 공간’, ‘장애물을 만나도 방향을 따라 계속 전진하는 느낌’과 가장 직접적인 서사 접점이 있다. 귀여움은 바흐의 단순한 형태와 표정에 맡기고, 색은 활력과 탐색 의지를 담당하게 할 수 있다. 전문적인 도구 화면과 대중적인 서비스 입구를 묶는 데도 이 역할 분담이 적합하다고 판단한다.

선명한 색을 기억 장치로 쓰고, 중립색과 글자색으로 실제 화면을 지탱하는 구조를 주 레퍼런스로 선택한다. 최종 색조는 Monzo·Mailchimp를 참고한 대안과 같은 조건에서 비교한다. 세 브랜드의 원색을 한 팔레트에 모두 넣지 않는다.

## 띠로리만의 결합 원칙

1. **서비스는 공통 맥락으로 연결한다.** ‘다른 앱 보기’ 목록보다 작품·아티스트·공연에서 다음 행동을 안내한다. 예를 들어 음원 감상에서 관련 악보를 찾거나 연습에서 공연 정보를 보는 흐름을 검토한다. 이 흐름은 설계 제안이며 현재 구현된 기능으로 소개하지 않는다. 실제 연결에는 식별 정보·권리·연결 가능 여부를 확인해야 한다.
2. **가족성은 고정하고 역할은 구별한다.** 모브랜드 표기, 워드마크 규칙, 아이콘의 시각적 무게, 공통 컨트롤과 문체를 공유한다. 앱별 기능 실루엣으로 구별하고 색만으로 제품을 식별하게 하지 않는다. 공통 대표색을 먼저 검토한 뒤 앱별 강조색의 필요성을 판단한다.
3. **귀여움의 밀도를 조절한다.** 소개·빈 화면·완료에는 짧고 단순한 바흐를 쓰고 악보·사보 작업 면에는 정보와 조작을 우선한다. 카드 안에 카드를 반복하거나 모든 컨트롤을 과도하게 둥글게 만들지 않는다.
4. **대표색과 행동색의 역할을 나눈다.** 대표색이 작은 글자나 버튼에 맞지 않으면 읽기 좋은 행동용 파생색을 별도로 둔다. 오류·주의·성공, 주석·성부·재생 위치는 고유한 의미를 유지한다. 기존 악보 데이터의 색을 브랜드색으로 바꾸지 않는다.
5. **흰 가발과 살구색 얼굴을 함께 본다.** 브랜드색 한 조각만 평가하지 않고 바흐·음형·한글 제품명과 함께 평가한다. 밝은 화면과 다크 화면에서 캐릭터와 주요 버튼이 모두 분명해야 한다.

공통 비교물은 한글·영문 워드마크, 음형과 놀란 바흐, 플레이·스코어·스튜디오의 작은 앱 아이콘, 모바일 악보함, 데스크톱 사보 툴바, 다크 화면, 주요 버튼·선택·오류 상태다. 소개 배너의 매력과 장시간 작업 화면의 편안함을 함께 평가한다.

판단 질문은 ‘띠로리라는 이름과 어울리는가’, ‘바흐가 자연스럽게 귀여운가’, ‘서로 다른 앱이 한 가족으로 읽히는가’, ‘기존 유명 서비스와 구별되는가’, ‘글자·선택·오류를 색각 차이와 확대 환경에서도 식별할 수 있는가’다. 대비·회색조·작은 아이콘 검토는 후보 팔레트를 만든 뒤 수행하며 이 문서만으로 통과했다고 기록하지 않는다.

색 선정 후 브랜드 입력과 의미 토큰의 소유 원본을 갱신하고 제작 자산·공통 컴포넌트를 재생성한다. 제품에 적용하는 작업에서는 해당 앱의 화면·접근성·배포 메타데이터도 함께 갱신한다. 현재 조사 작업은 제품 코드나 출시 문구를 변경하지 않는다.
