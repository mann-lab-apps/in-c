# Native audio test fixtures

`movement_1.wav` and `movement_2.wav` are deterministic synthetic PCM files
generated by `tool/generate_audio_fixtures.dart`. They contain short arpeggiated
tones and marker tones, not a third-party performance or recording.

- Sample format: 16-bit mono PCM WAV
- Sample rate: 22,050 Hz
- Duration: 2.4 seconds per file
- Rights: generated specifically for this repository; no third-party source
- Purpose: native decoder, queue, position, completion, and persistence tests

Each file includes 100 ms marker tones at 0.08 s, 1.12 s, and 2.15 s plus a
100 ms silent window at 0.22 s. The two files use distinct marker frequencies.
`lib/audio_test_fixture.dart` validates the canonical RIFF/PCM header, sample
rate, duration, silent window, and marker frequency estimate. This proves the
fixture bytes, not physical speaker output.

Regenerate from the app directory with:

```sh
dart run tool/generate_audio_fixtures.dart
```

Check that committed files still match the deterministic generator:

```sh
dart run tool/generate_audio_fixtures.dart --check
```

`movement_1_aac.m4a` is a synthetic AAC-in-M4A derivative of `movement_1.wav`,
generated on macOS with `/usr/bin/afconvert -f m4af -d aac`. Its codec contract
is checked with `afinfo`; AAC encoder metadata is not byte-stable, unlike PCM.

`movement_1_alac.m4a` and `movement_1.flac` use the same generated source with
macOS `afconvert -f m4af -d alac` and `afconvert -f flac -d flac` respectively.
They are repository-generated derivatives, not third-party performances.
No external encoder binary is downloaded. The local macOS encoder does not
support MP3 output; MP3 validation remains separate and unverified here.

`dart run tool/verify_decoded_audio.dart` decodes all four first-movement formats
with the host's actual `afconvert` decoder. It emits input/output hashes, duration,
mono channel count, peak/clipping count, three marker frequency/RMS measurements
and a central quiet-window RMS. Tolerances are fixed in `audio_signal_analysis.dart`
and mutation tests reject silence, clipping, wrong markers and malformed chunks.
AAC is lossy, so quiet-window RMS below 100 PCM16 units is allowed; this is a
fixture regression threshold, not a psychoacoustic quality threshold.

The capture point is **host decoder PCM**, not iOS output, OS loopback or a speaker
recording. These mono fixtures do not prove stereo routing, gapless transitions,
interruption behavior, Bluetooth quality or audibility. iOS native FLAC transport
is tested separately in `audio_playback_integration_test.dart`.
