# Changes

## iOS screen-lock playback - 0.1.0+2 - 2026-10-30

- iOS에서 화면을 잠그거나 다른 앱으로 전환할 때 재생을 유지하고 현재 위치를 저장한다. 음악용 오디오 세션과 `UIBackgroundModes: audio`를 사용하며 추가 의존성은 없다.
- 전화 등 interruption과 출력 장치 분리 시 일시정지하고 자동 재개하지 않는 정책은 유지한다. Android는 기존 background 일시정지 정책을 사용한다.
- 잠금 화면 조작·헤드폰 버튼·CarPlay 및 강제 종료 후 자동 재생은 제공하지 않는다. 물리 iPhone Xs 잠금 청감 검증은 사용자 QA로 남긴다.

## Playlists and clearer file tools - 2026-10-26

- 보관함의 폴더 분류 자리에 재생목록을 배치했다. 생성·이름 변경·검색하며 여러 곡 추가·드래그 순서 변경·제거·삭제와 저장 순서 재생을 지원한다. 곡·앨범·전체 검색·현재 재생에서 바로 담거나 새 목록을 만들 수 있다. 폴더별 보기는 도구 메뉴에서 계속 접근한다.
- 파일 ID를 저장하는 SQLite schema v15와 논리 백업을 추가했다. 기존 v14 백업도 읽고, 누락 곡은 목록에 남기되 재생 큐에서는 제외한다.
- `가져오기·파일 상태`와 `음원 정보·파일 복구`로 고급 도구의 역할을 명확히 했다. 외부 원본과 태그는 변경하지 않는다.

## Library screen and Play icon preview - 2026-10-26

- 새 공통 블루 토큰을 Play 기본 테마에 반영했다. 밝은 화면의 행동·포커스는 블루, 안내는 중립색이며 라이트·다크 보관함에서 확인했다.
- 보관함 제목 위의 앱 아이콘·앱 이름 반복 표시는 제거했다. 런처 아이콘은 유지한다.
- 보관함을 큰 제목·구분선 분류 목록·최근 추가 앨범/곡 카드 형태로 다시 구성했다. 카드에서 앨범 곡 목록 또는 태그 없는 곡 재생으로 이동한다.
- 최신 Play 아이콘 후보 08을 iOS/Android 개발용 런처에 적용했다. 최종 출시 승인은 별개다.
- 기존 파일 직접 재생·작품 정리·미니플레이어·큐와 화면 이동 계약을 유지한다.

## Library browse refinement - 2026-10-26

- 보관함의 곡·앨범·아티스트·폴더 행을 공통 평면 Item으로 통일하고 중복 보관함 제목을 제거했다.
- 분류 안 검색과 안정적인 곡 정렬을 추가했다. 앨범의 디스크/트랙 순서를 유지하고, 검색·정렬 중 큐와 현재 곡을 보존한다.
- 누락 파일의 재생 동작을 파일 상태 확인으로 바꾸고 기존 파일 정리로 연결했다. 저장 모델, 오디오 엔진, 출시 버전은 변경하지 않았다.

## Product Design R3 Play - 2026-10-25

- 파일별 가져오기 결과를 가져옴·중복·분석 대기·실패·취소로 구분하고 실패한 선택만 재시도한다. 완료한 파일은 유지한다.
- 선택한 파일에서 작품·녹음 등록 폼으로 이어가며, 저장 실패 시 입력을 보존하고 재시도한다. 등록 뒤 후속 처리만 실패하면 중복 등록을 막고 닫기 전에 저장 사실을 알린다. 실제 재생 엔진이 playing을 보고한 뒤에만 첫 재생 안내를 표시한다.
- 유효한 앱 관리 음원의 공유 성공 뒤 Score에서 대상 악보와 연결 파일을 직접 선택하는 방법을 안내한다. 공유 성공을 Score 저장 완료로 표현하지 않는다.
- 즉시 곡 재생과 기존 카탈로그/큐/ID/원본 파일 정책은 유지한다. 배포나 물리 기기 검수는 아니다.

## Local Library First - 2026-10-25

- 기본 진입점을 보관함으로 옮기고 곡·앨범·아티스트·폴더와 최근 가져온 음악을 제공한다.
- 가져온 파일을 작품·녹음으로 등록하지 않아도 곡을 탭해 직접 재생한다.
- 재생 큐가 있을 때만 축약 조작과 재생 상세를 표시한다. 기존 클래식 정리·랜덤 재생·감상·IMSLP는 선택적 도구로 보존한다.
- 기존 카탈로그/파일 ID와 SQLite schema, 원본 파일을 유지한다. 배포 승인이나 촬영 완료를 뜻하지 않는다.

## Product Design R2 - 2026-10-25

- 같은 작품/녹음의 큐 설명을 묶고 악장 순서·현재 항목·음원 정보에 집중한다.
- 다른 작품/녹음 탐색 중에도 옆 재생 영역 또는 하단 축약 조작과 재생 상세를 제공한다.
- 엔진 snapshot과 탐색 route를 분리하고 큐·position·ID·retry 정책을 보존한다.
- seek 중 엔진 update와 곡 변경/pause/error, 확정 명령 중복, 키보드 시간 조작을 검증한다.
- 공통 API·오디오 엔진·schema·버전은 유지한다. iOS YAML과 촬영 동선을 갱신한다.

## Uncommitted - Product Design R1 - 2026-10-25

- 라이브러리/현재 재생/관리/감상 보기로 기존 기능의 진입 경로를 정리한다.
- 작품 필터·정렬과 평평한 작품/녹음/악장 행을 적용한다. 원래 엔터티 ID는 유지한다.
- 엔진 큐·위치를 보존하고 오류 재시도, 길이 미확정, seek draft를 구분한다.
- 큰 글자의 큐 배지와 시간 표시를 보완한다. 공통 진행 표시 API는 바꾸지 않는다.
- iOS 메타데이터의 화면 동선과 촬영 assertions를 갱신한다. pending 상태를 유지한다.
- 검증 증거와 물리 환경의 한계는 README의 R1 인계 링크를 따른다.
  배포·새 버전·런처/대표색 확정은 아니다.

## 0.1.0+1 Development Checkpoint - 2026-10-23

출시가 아닌 개발 체크포인트다. 버전과 SQLite schema v14는 유지한다.

### 라이브러리와 재생

- 로컬 파일 가져오기·스캔과 작곡가/작품/녹음/악장 카탈로그 관리.
- SQLite 저장, legacy JSON 마이그레이션, 백업·복원과 누락 파일 재연결.
- 사용자 메타데이터 교정, 중복 병합·되돌리기, 검색과 로컬 discovery.
- MusicBrainz 후보 검토와 IMSLP 참조·가져오기 경계.
- 실제 로컬 foreground 재생, 악장 순서를 유지하는 큐, 감상 이력과 위치 복원.
- 공통 `ddirori_ui`와 플레이 전용 표시 컴포넌트 분리.

### 최근 안정성 보강

- 전체 초기화 전에 재생·위치·이력 저장을 정리하고 큐 snapshot도 삭제한다.
- 큐 저장 실패 뒤 동일 상태 재시도를 허용하고 시작 시 idle로 기존 큐를 지우지 않는다.
- 재생 진단 재실행 시 이전 청감 응답을 비우고 오류 뒤 재시도를 제공한다.
- 좁은 화면과 글자 200%에서 섹션 제목·도구의 넘침을 방지한다.
- 로컬 QA 실행기에 명령 결과·로그 hash·소스 fingerprint를 기록한다.
- 최초 checkout에서 Flutter가 만드는 iOS 플러그인 등록 파일은 소스 변경 판정에서 제외한다.
  실제 native 코드·공통 UI 생성 토큰·오디오 자산의 변경 감지는 유지한다.
- 합성 WAV/AAC/ALAC/FLAC 디코더 신호 검사와 5000트랙 회귀 검증을 추가한다.

### 검증과 남은 범위

- 깨끗한 체크포인트 checkout에서 플레이 321개 테스트, 정적 분석, format, fixture와 host PCM 검사를 통과했다.
- iOS Simulator 결과와 fake/host/물리 환경의 경계는
  [QA 기록](../../docs/quality/classical-local-library-local-qa-2026-10-23.md)을 따른다.
- MP3 실측, 실제 VoiceOver·Files/iCloud 제공자·출력 장치·interruption은 미검증으로 남는다.
- 최종 디자인 승인, 공개 URL, 스토어 촬영·pinning·서명·업로드·출시는 보류한다.
  현재 자산의 버전 관리는 최종 디자인 승인이나 배포 승인을 뜻하지 않는다.

### 저장소 경계

- 앱 실행에 필요한 Flutter 공통 UI는 별도 의존성 체크포인트로 관리한다.
- 앱별 iOS YAML과 캡처 adapter만 플레이 범위로 관리한다. 공통 배포 엔진과 다른 앱의
  변경은 각 담당 작업에서 정리하며, 로컬 검증 결과를 공개 배포 증거로 간주하지 않는다.
- build, SDK cache, 로컬 QA 로그, 인증서와 개인 음원은 커밋 대상이 아니다.
